Two Names, One List (Aliasing)

Step through the program one line at a time. Watch the frames (each function call's variables) and the objects they point to. Keys: →/Space next, ← back.

In Python a variable doesn't hold a list itself: it holds a reference to (an arrow pointing at) a list object. So y = x doesn't copy the list. It makes y point to the same list as x: two names, one list.

How it works

What to watch for:

  1. y = x: a second arrow appears, pointing to the same list.
  2. y.append(4) changes that one list, so printing x shows the 4 too.
  3. z = x[:]: the slice builds a new list, a copy, with its own arrow.
  4. z.append(5) changes only the copy; x is unaffected.
  5. x is y asks "same object?": True. x is z is False, even though the lists started out equal.

    Frames live on the call stack. Every function call gets a new
         frame holding its own variables, and the frame is pushed onto the
         call stack (the newest call is at the bottom of the list below).
         When a call returns, its frame is popped and the caller carries on where it left off.
    
      
    Recursion pushes one frame per call until it reaches the base case,
         then unwinds as each call returns. The stack is limited: Python allows about 1000
         frames by default (sys.getrecursionlimit()). A recursive function that never
         reaches its base case keeps pushing frames until the stack runs out and Python stops with
         RecursionError: maximum recursion depth exceeded, a stack overflow.
