Mutable vs Immutable

This is one of the most important concepts in Python.

In C, every variable is a named memory location — you can always write a new value into it:

int x = 5;
x = 10;   // always allowed — x is just a memory location

In Python, a variable is a name that refers to an object. The object itself may or may not allow modification:

Term Meaning
Immutable Once created, the object’s contents cannot be changed
Mutable The object’s contents can be changed after creation

You’ve already seen this

Integers and strings in Python are immutable.

When you write:

x = 5
x = 10

You are not modifying the integer 5. You are making x point to a new object (10).

The object 5 itself never changed — Python created a brand new 10 object and re-bound the name x to it.

Key idea: In Python, assignment (=) always creates a new name binding. Whether the object itself can be modified depends on whether its type is mutable.

Why does mutability matter for containers?

Python’s four built-in container types split cleanly along this line:

Type Ordered Mutable Indexed by Duplicates
tuple Yes No position Yes
list Yes Yes position Yes
dict Yes* Yes key keys: No, values: Yes
set No Yes — (not indexed) No

*Dictionaries preserve insertion order as of Python 3.7

Understanding mutability tells you what operations are legal on each type — that’s the public interface.

Tuples

A tuple is an ordered, immutable sequence.

  • Created with parentheses ( )
  • Elements have fixed positions (indices starting at 0)
  • Once created: you cannot add, remove, or change elements
  • Can hold values of different types
  • Duplicate values are allowed
point = (3, 7)
rgb   = (255, 128, 0)
mixed = (42, "hello", True, 3.14)

print(point)
print(rgb)
print(mixed)
Output
(3, 7)
(255, 128, 0)
(42, 'hello', True, 3.14)

Tuple — Public Interface

Because tuples are immutable, their interface is intentionally small:

Operation Syntax Description
Access by index t[i] Get element at position i
Length len(t) Number of elements
Membership test x in t True if x is in the tuple
Count occurrences t.count(x) How many times x appears
Find index t.index(x) First position where x appears
Iterate for x in t: Loop over elements

Notice: No append, no remove, no pop — because the tuple cannot be modified.

grades = (85, 92, 78, 92, 88)

print("Length:     ", len(grades))
print("First:      ", grades[0])
print("Last:       ", grades[-1])
print("92 appears: ", grades.count(92), "times")
print("92 first at:", grades.index(92))
print("78 in grades:", 78 in grades)
Output
Length:      5
First:       85
Last:        88
92 appears:  2 times
92 first at: 1
78 in grades: True

Immutability in action

point = (3, 7)
point[0] = 10    # TypeError: 'tuple' object does not support item assignment
Output
---------------------------------------------------------------------------
TypeError                                 Traceback (most recent call last)
Cell In[5], line 2
      1 point = (3, 7)
----> 2 point[0] = 10    # TypeError: 'tuple' object does not support item assignment

TypeError: 'tuple' object does not support item assignment

Python enforces immutability at runtime — attempting to modify a tuple raises a TypeError.

When to use a tuple:
Use a tuple when the collection of values is fixed and should not change — for example, a coordinate, an RGB colour, or a record that should stay constant.

Lists

A list is an ordered, mutable sequence.

  • Created with square brackets [ ]
  • Elements have positions (indices starting at 0)
  • You can add, remove, and change elements after creation
  • Can hold values of different types
  • Duplicate values are allowed
fruits  = ["apple", "banana", "cherry"]
numbers = [10, 20, 30, 40]
mixed   = [1, "hello", True, 3.14]

print(fruits)
print(numbers)
Output
['apple', 'banana', 'cherry']
[10, 20, 30, 40]

List — Public Interface

Because lists are mutable, their interface is much richer:

Operation Syntax Description
Access by index lst[i] Get element at position i
Assign by index lst[i] = x Replace element at position i
Length len(lst) Number of elements
Membership test x in lst True if x is in the list
Add to end lst.append(x) Adds x at the end
Insert at position lst.insert(i, x) Inserts x before index i
Remove by value lst.remove(x) Removes first occurrence of x
Remove by index lst.pop(i) Removes element at index i, returns it
Delete element(s) del lst[i] Removes element at index i
Iterate for x in lst: Loop over elements

Mutability in action

fruits = ["apple", "banana", "cherry"]
print("original: ", fruits)

fruits[1] = "mango"        # replace an element
print("after replace:", fruits)

fruits.append("grape")     # add to the end
print("after append:", fruits)

fruits.remove("apple")     # remove by value
print("after remove:", fruits)
Output
original:  ['apple', 'banana', 'cherry']
after replace: ['apple', 'mango', 'cherry']
after append: ['apple', 'mango', 'cherry', 'grape']
after remove: ['mango', 'cherry', 'grape']

Tuple vs List — The Key Distinction

t = (1, 2, 3)   # tuple — immutable
l = [1, 2, 3]   # list  — mutable
Tuple List
Read elements Yes Yes
Change elements No Yes
Add elements No Yes
Remove elements No Yes

The interface reflects the contract:

  • A tuple says: “these values are fixed”
  • A list says: “this collection can grow and change”

Choose the type that matches your intent.

del in Python

Python’s del keyword does two different but related things depending on context:

  1. Deletes a name binding — removes a variable name from scope
  2. Removes an element from a container — works on lists and dictionaries

Comparing to C

In C, free() releases allocated memory directly:

int *p = malloc(sizeof(int));
*p = 42;
free(p);    // memory is released; p is now a dangling pointer

In Python, memory management is automatic. Python tracks how many names refer to each object (called reference counting):

x = [1, 2, 3]   # the list has 1 reference: x
y = x            # the list now has 2 references: x and y
del x            # removes the name x — but the list still exists via y
print(y)         # [1, 2, 3]  <-- still alive

del x does not free the object — it removes the name. Python frees the object automatically when the reference count reaches zero.

x = [1, 2, 3]
y = x           # y and x refer to the SAME list object

del x           # remove the name x
print(y)        # the list still exists — y still refers to it
Output
[1, 2, 3]
print(x)        # NameError: name 'x' is not defined
Output
---------------------------------------------------------------------------
NameError                                 Traceback (most recent call last)
Cell In[10], line 1
----> 1 print(x)        # NameError: name 'x' is not defined

NameError: name 'x' is not defined

del on containers

del can also remove elements from a mutable container by index (lists) or by key (dictionaries).

letters = ['A', 'B', 'C', 'D', 'E']
print("before:", letters)

del letters[2]          # remove element at index 2 ('C')
print("after del [2]:", letters)

del letters[1:3]        # remove a range of elements
print("after del [1:3]:", letters)
Output
before: ['A', 'B', 'C', 'D', 'E']
after del [2]: ['A', 'B', 'D', 'E']
after del [1:3]: ['A', 'E']

You cannot use del on a tuple element — tuples are immutable:

t = (1, 2, 3)
del t[0]   # TypeError: 'tuple' object doesn't support item deletion

The mutability of the type determines what del can do to it.

del — Summary

Usage Effect
del x Removes the name x from the current scope
del lst[i] Removes element at index i from the list
del lst[i:j] Removes the slice from index i to j-1
del d[key] Removes the key–value pair from the dictionary

Key points (from a C perspective):

  • del removes a reference, not necessarily the memory
  • Python frees memory automatically when no more references exist
  • You cannot delete from an immutable type (tuple, string)

Dictionaries

A dictionary stores key–value pairs.

  • Created with curly braces { key: value, ... }
  • Indexed by key, not by position
  • Keys must be immutable (strings, integers, tuples)
  • Values can be anything
  • Mutable: entries can be added, updated, and removed
  • Keys must be unique; values do not need to be
student = {
    "name": "Alice",
    "grade": 88,
    "enrolled": True
}

print(student)
print(student["name"])    # access by key
print(student["grade"])
Output
{'name': 'Alice', 'grade': 88, 'enrolled': True}
Alice
88

Dictionary — Public Interface

Operation Syntax Description
Access value d[key] Get value for key (error if missing)
Safe access d.get(key) Get value, returns None if key not found
Add / update d[key] = value Add new entry or overwrite existing
Delete entry del d[key] Remove the key–value pair
Membership test key in d True if key exists
Length len(d) Number of key–value pairs
All keys d.keys() View of all keys
All values d.values() View of all values
All pairs d.items() View of (key, value) pairs
Iterate for k in d: Loop over keys 
grades = {"Alice": 85, "Bob": 92, "Carol": 78}
print("original:", grades)

grades["Dave"] = 88        # add a new entry
print("after add:", grades)

grades["Alice"] = 90       # update an existing entry
print("after update:", grades)

del grades["Bob"]          # remove an entry
print("after del:", grades)
Output
original: {'Alice': 85, 'Bob': 92, 'Carol': 78}
after add: {'Alice': 85, 'Bob': 92, 'Carol': 78, 'Dave': 88}
after update: {'Alice': 90, 'Bob': 92, 'Carol': 78, 'Dave': 88}
after del: {'Alice': 90, 'Carol': 78, 'Dave': 88}

Why must keys be immutable?

Dictionaries locate values using a hash of the key — a numeric fingerprint computed from the key’s value.

If a key could change after being inserted, its hash would change too, and the dictionary would no longer be able to find it.

# Strings and integers are immutable → valid keys
d = {"name": "Alice", 42: "answer"}

# Lists are mutable → cannot be used as keys
d[[1, 2]] = "test"   # TypeError: unhashable type: 'list'

This is another place where mutability has direct practical consequences.

Iterating over a Dictionary

grades = {"Alice": 90, "Bob": 85, "Carol": 92}

# Iterate over key-value pairs together (most common)
for name, score in grades.items():
    print(name, "->", score)
Output
Alice -> 90
Bob -> 85
Carol -> 92
# Iterating over just keys (default behaviour)
for name in grades:
    print(name)
Output
Alice
Bob
Carol

Sets

A set is an unordered collection with no duplicate values.

  • Created with curly braces { } (but no key–value pairs)
  • Not indexed — you cannot access elements by position
  • Mutable: you can add and remove elements
  • Automatically discards duplicates
colours = {"red", "green", "blue", "red"}   # 'red' appears twice
print(colours)   # only one 'red' — duplicates are silently removed

colours.add("yellow")
print(colours)

colours.remove("green")
print(colours)
Output
{'red', 'blue', 'green'}
{'red', 'yellow', 'blue', 'green'}
{'red', 'yellow', 'blue'}

Set — Public Interface

Operation Syntax Description
Add element s.add(x) Adds x (no effect if already present)
Remove element s.remove(x) Removes x (error if not present)
Membership test x in s True if x is in the set
Length len(s) Number of elements
Union s1 | s2 All elements from both sets
Intersection s1 & s2 Elements in both sets
Difference s1 - s2 Elements in s1 but not s2

Notice: No indexing (s[0]) — sets have no notion of order or position.

Sets are unordered

s1 = {3, 1, 2}
s2 = {1, 2, 3}

print(s1 == s2)   # True — same elements, order doesn't matter

s1[0]             # TypeError: 'set' object is not subscriptable
Output
True
---------------------------------------------------------------------------
TypeError                                 Traceback (most recent call last)
Cell In[17], line 6
      2 s2 = {1, 2, 3}
      4 print(s1 == s2)   # True — same elements, order doesn't matter
----> 6 s1[0]             # TypeError: 'set' object is not subscriptable

TypeError: 'set' object is not subscriptable

When to use a set:
Use a set when you care about membership and uniqueness, not order — for example, tracking which items have been seen, or computing overlaps between two groups.

Summary

Type Syntax Ordered Mutable Indexed by Duplicates
tuple (a, b, c) Yes No position Yes
list [a, b, c] Yes Yes position Yes
dict {k: v} Yes* Yes key keys: No
set {a, b, c} No Yes not indexed No

*Preserves insertion order as of Python 3.7

del reminder:

  • del x — removes a name binding
  • del lst[i] / del d[key] — removes from a mutable container
  • Cannot delete from an immutable type
