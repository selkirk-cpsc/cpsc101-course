Defining Functions

You already know functions from C. The idea is the same: give a block of code a name so you can reuse it.

The syntax is different:

// C
int add(int a, int b) {
    return a + b;
}
# Python
def add(a, b):
    return a + b
C Python
Keyword return type then name def
Parameter types declared explicitly not declared
Return type declared explicitly not declared
Body delimited by { } indentation

Python is dynamically typed

In C, every variable and parameter has a fixed type declared at compile time.
In Python, types are determined at runtime — the same function can accept different types:

def add(a, b):
    return a + b

add(3, 4)          # works: 7
add("hello", "!")  # also works: "hello!"
add(3, "hello")    # TypeError at runtime — + not defined for int and str

This flexibility is powerful, but it means you are responsible for using functions with compatible types.

The function’s name, parameters, and docstring (coming soon) define its intended interface — the types aren’t enforced by the language.

def greet(name):
    print("Hello,", name)

greet("Alice")
greet("Bob")
Output
Hello, Alice
Hello, Bob
def add(a, b):
    return a + b

result = add(3, 4)
print(result)
Output
7

Parameters and Arguments

A quick terminology note:

  • Parameter — the name in the function definition (def add(a, b) → a and b are parameters)
  • Argument — the value you pass when calling the function (add(3, 4) → 3 and 4 are arguments)

Python supports three ways to pass arguments:

Style Description
Positional Arguments matched to parameters by order (same as C)
Default Parameters have a pre-set value used when not provided
Keyword Arguments passed by name, order doesn’t matter

Positional Arguments

Arguments are matched to parameters by their position — exactly like C.

def describe(animal, sound):
    print("A", animal, "goes", sound)

describe("cat", "meow")   # animal="cat", sound="meow"
describe("meow", "cat")   # order matters — this is wrong but Python won't catch it
Output
A cat goes meow
A meow goes cat

Default Parameters

Python lets you assign a default value to a parameter. If the caller doesn’t supply that argument, the default is used.

This does not exist in C.

def greet(name, greeting="Hello"):
    print(greeting + ",", name)

greet("Alice")                  # uses default: Hello, Alice
greet("Bob", "Good morning")    # overrides default: Good morning, Bob
Output
Hello, Alice
Good morning, Bob

Rule: Parameters with defaults must come after parameters without defaults.

def f(a, b=10):   # OK
    ...

def f(a=10, b):   # SyntaxError
    ...

Keyword Arguments

When calling a function, you can pass arguments by name instead of by position.
This makes calls more readable and lets you reorder arguments.

def describe(animal, sound):
    print("A", animal, "goes", sound)

# All three calls are equivalent:
describe("cat", "meow")                    # positional
describe(animal="cat", sound="meow")       # keyword
describe(sound="meow", animal="cat")       # keyword, different order
Output
A cat goes meow
A cat goes meow
A cat goes meow
def power(base, exponent=2):
    return base ** exponent

print(power(3))              # 9  (exponent defaults to 2)
print(power(2, 10))          # 1024
print(power(2, exponent=8))  # 256 — keyword arg skips positional matching
Output
9
1024
256

Return Values

Single value and None

A function returns a value using return — same concept as C.

In C, a function that returns nothing is declared void.
In Python, a function that doesn’t return anything automatically returns None.

def greet(name):
    print("Hello,", name)
    # no return statement

result = greet("Alice")
print("return value:", result)   # None
Output
Hello, Alice
return value: None

None is Python’s way of representing “no value”. It is its own type (NoneType) and is the only value of that type.

print(type(None))   # <class 'NoneType'>

Multiple Return Values

In C, a function can only return one value. To get multiple values out, you pass pointers.

In Python, a function can return multiple values — they are packed into a tuple automatically.

This is one of the places where tuples from Part 1 become immediately useful.

def min_max(numbers):
    return min(numbers), max(numbers)   # returns a tuple

result = min_max([4, 1, 9, 2, 7])
print(result)          # (1, 9)  <-- a tuple
print(type(result))    # <class 'tuple'>
Output
(1, 9)
<class 'tuple'>
# Use tuple unpacking to capture each value separately
lo, hi = min_max([4, 1, 9, 2, 7])
print("min:", lo)
print("max:", hi)
Output
min: 1
max: 9

Multiple return values — C comparison

In C, returning two values requires pointers:

void min_max(int arr[], int n, int *lo, int *hi) {
    // write results through pointers
}

int lo, hi;
min_max(arr, n, &lo, &hi);

In Python:

def min_max(numbers):
    return min(numbers), max(numbers)

lo, hi = min_max(numbers)

The Python version is cleaner because the function’s interface (what it produces) is expressed directly in the return statement, not through side-effects on pointers.

Scope

Scope determines where a variable name is visible.

In C, scope is block-based: any variable declared inside { } is local to that block.

In Python, scope is function-based:

  • Variables defined inside a function are local — they don’t exist outside it
  • Variables defined outside all functions are global
x = 10          # global

def f():
    x = 99      # local — a completely separate variable
    print(x)    # 99

f()
print(x)        # 10  — global x is unchanged
x = 10          # global variable

def f():
    x = 99      # local variable — shadows the global
    print("inside f: x =", x)

f()
print("outside f: x =", x)   # global x is unchanged
Output
inside f: x = 99
outside f: x = 10
message = "Hello"    # global

def print_message():
    print(message)   # reads the global — no local 'message' defined here

print_message()
Output
Hello

Rule: A function can read a global variable, but any assignment inside a function creates a new local variable unless you explicitly declare global.

Local variables don’t exist outside the function

def compute():
    result = 42

compute()
print(result)   # NameError: name 'result' is not defined
Output
(1, 9)

Local variables are created when the function is called and destroyed when it returns.

To get a value out of a function, use return — don’t rely on writing to a global.

This mirrors good C practice: return values through return, not global state.

One key difference from C: no block scope

In C, a variable declared inside an if or for block is only visible in that block.

In Python, an if or for block does not create a new scope — variables assigned inside them are visible in the whole function:

def f():
    if True:
        y = 5       # in C, y would be local to this if-block
    print(y)        # in Python, y is visible here too — prints 5

Only functions (and classes) create new scopes in Python.

Functions and Mutability

What happens to an argument when you pass it to a function?
The answer depends on whether the object is mutable or immutable — the theme from Part 1.

In C, you choose: pass by value (copy) or pass by pointer (reference).
In Python, all arguments are passed by object reference — but mutability determines whether the function can modify what you passed.

Passing an immutable object

Integers, strings, and tuples are immutable. A function cannot modify them.

This behaves like pass-by-value in C.

def double(x):
    x = x * 2     # creates a new local binding — does NOT change the caller's x
    print("inside:  x =", x)

n = 5
double(n)
print("outside: n =", n)   # unchanged
Output
inside:  x = 10
outside: n = 5

Passing a mutable object

Lists and dictionaries are mutable. A function can modify them in-place, and the changes are visible to the caller.

This behaves like passing a pointer in C.

def append_zero(lst):
    lst.append(0)   # modifies the list object in place

numbers = [1, 2, 3]
append_zero(numbers)
print(numbers)   # [1, 2, 3, 0] — the original list was modified
Output
[1, 2, 3, 0]

The function and the caller share the same list object. Mutating it inside the function mutates it everywhere.

Mutation vs Rebinding — an important distinction

def replace(lst):
    lst = [99, 98, 97]   # rebinds the LOCAL name — does NOT affect the caller

numbers = [1, 2, 3]
replace(numbers)
print(numbers)   # still [1, 2, 3]
Output
[1, 2, 3]

Assignment (lst = ...) inside a function always creates or rebinds a local name.
Methods like lst.append() or lst[i] = x mutate the object the name points to.

Action Effect on caller’s object
lst.append(x) Modified — same object
lst[i] = x Modified — same object
lst = [...] No effect — local rebinding

Mutability and function arguments — summary

Argument type Can function modify caller’s object? C analogy
int, str, tuple (immutable) No pass by value
list, dict, set (mutable) Yes, if mutated in place pass by pointer

Practical consequence:
If you write a function that takes a list and modifies it, the caller’s list changes.
If you don’t want that, pass a copy: my_function(my_list[:]).

def append_zero(lst):
    lst.append(0)

numbers = [1, 2, 3]
append_zero(numbers[:])   # pass a copy — original is protected
print(numbers)            # [1, 2, 3] — unchanged
Output
[1, 2, 3]

Docstrings

A docstring is a string literal placed immediately after the def line.
It documents what the function does — its purpose, parameters, and return value.

def function_name(param1, param2):
    """One-line summary of what the function does.

    Longer description if needed.

    Parameters:
        param1: description
        param2: description

    Returns:
        description of return value
    """
    ...

In C, you’d write a comment above the function. Python formalises this into the language — the docstring is stored on the function object and accessible via help().

def min_max(numbers):
    """Return the minimum and maximum values in a list.

    Parameters:
        numbers: a non-empty list of comparable values

    Returns:
        A tuple (minimum, maximum)
    """
    return min(numbers), max(numbers)

help(min_max)
Output
Help on function min_max in module __main__:

min_max(numbers)
    Return the minimum and maximum values in a list.

    Parameters:
        numbers: a non-empty list of comparable values

    Returns:
        A tuple (minimum, maximum)

The docstring is part of a function’s public interface — it tells the caller what the function expects and what it produces, without needing to read the implementation.

Putting It All Together

Let’s write a small function that uses everything from this lecture and Part 1:

  • Takes a list of student grade dictionaries
  • Returns a tuple with the class average and the top scorer’s name
def class_summary(records):
    """Return summary statistics for a list of student records.

    Parameters:
        records: list of dicts, each with 'name' and 'grade' keys

    Returns:
        A tuple (average_grade, top_student_name)
    """
    total = 0
    top_name  = records[0]["name"]
    top_grade = records[0]["grade"]

    for student in records:
        total += student["grade"]
        if student["grade"] > top_grade:
            top_grade = student["grade"]
            top_name  = student["name"]

    average = total / len(records)
    return average, top_name
students = [
    {"name": "Alice",  "grade": 88},
    {"name": "Bob",    "grade": 95},
    {"name": "Carol",  "grade": 76},
    {"name": "Dave",   "grade": 91},
]

avg, top = class_summary(students)
print(f"Class average: {avg:.1f}")
print(f"Top student:   {top}")
Output
Class average: 87.5
Top student:   Bob

Summary

Concept Python C equivalent
Define a function def name(params): type name(params) { }
Default parameters def f(x, y=0): not supported
Keyword arguments f(y=1, x=2) not supported
No return value returns None void
Multiple return values return a, b → tuple output pointers
Scope unit function block { }
Immutable argument cannot be modified pass by value
Mutable argument can be modified in place pass by pointer
Documentation docstring ("""..."""), help() comments

Key takeaway:
A function’s name, parameters, defaults, and docstring define its public interface.
Mutability determines whether passing an object to a function is safe or has side effects.
