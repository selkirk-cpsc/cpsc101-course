Introduction

So far, we have used classes to create instances (objects) that each store their own data.

In Python, a class can also store data and behaviour that belongs to the class itself (not to any one object).

This section introduces:

  • class-side data (shared attributes on the class)
  • class-side behaviour (methods that act on the class)
  • static behaviour (utility functions stored on the class)

Class Side Data

  • A class can have attributes too. These are called class variables (or class attributes).
  • Class variables are defined inside the class, but outside of any methods.
  • They are shared by all instances of the class.

Adding Class Variables

In our LabSample class, we will add a sample_count is a class variable:

class LabSample:
    """Represents a lab sample with repeated measurements 
    (e.g., pH, voltage, mass).
    """

    # Adding class variable sample_count
    sample_count = 0  # counts how many LabSample objects have been created
    ...

It lives on the class: LabSample.sample_count

Updating sample_count

sample_count is updated every time a new LabSample object is created by including LabSample.sample_count += 1 in the __init__ method:

class LabSample:
    """Represents a lab sample with repeated measurements (e.g., pH, voltage, mass)."""

    # Adding class variable sample_count
    sample_count = 0  # counts how many LabSample objects have been created

    def __init__(self, sample_id, units):
        self.sample_id = sample_id
        self.units = units
        self.measurements = []

        # Update class-side counter whenever a new sample is created
        LabSample.sample_count += 1
    ...

Since it is shared, all objects “contribute” to the same count.

class LabSample:
    """Represents a lab sample with repeated measurements (e.g., pH, voltage, mass)."""

    # -----------------------------
    # Class-side (shared) data
    # -----------------------------

    # Adding class variable sample_count
    sample_count = 0  # counts how many LabSample objects have been created

    # -----------------------------
    # Instance behaviour
    # -----------------------------

    def __init__(self, sample_id, units):
        self.sample_id = sample_id
        self.units = units
        self.measurements = []

        # Update class-side counter whenever a new sample is created
        LabSample.sample_count += 1

    def add_measurement(self, value):
        self.measurements.append(float(value))

    def mean(self):
        """Return the average measurement, or None if there are no measurements."""
        if len(self.measurements) == 0:
            return None
        return sum(self.measurements) / len(self.measurements)
    
    def __str__(self):
            # Build a readable one-line summary of the object
            n = len(self.measurements)
            return f"sample id: {self.sample_id}, units: {self.units}, sample size: {n}"
# Uncomment to set sample_count back to 0
# LabSample.sample_count = 0

s1 = LabSample("PH-017", "pH")
s2 = LabSample("V-204", "V")
s3 = LabSample("MASS-003", "g")
s4 = LabSample("PH-018", "pH")

print(F"Lab Sample Count: {LabSample.sample_count}")
Output
Lab Sample Count: 4

Class Methods

  • A class can also define behaviour that belongs to the class itself, not to any one object.
  • This behaviour is written as a class method.

What makes a method a class method?

  • It uses the decorator @classmethod (written on the line just above the method).
  • Its first parameter is usually named cls.
    • cls represents the class (similar to how self represents an object).
  • Class methods are often used to:
    • update class variables,
    • provide “alternate constructors,”
    • or manage shared settings.

Adding a Class Method from_measurements()

In our LabSample class, we will introduce a class method that provides an “alternate constructor”:

  • from_measurements(cls, sample_id, units, measurements)
    Builds a new LabSample from an existing list of measurements (an “alternate constructor”).
@classmethod
def from_measurements(cls, sample_id, units, measurements):
    """
    Alternate constructor: build a LabSample from an existing list of measurements.
    """
    s = cls(sample_id, units)
    for x in measurements:
        s.add_measurement(x)
    return s

Calling from_measurements()

You call a class method using the class name and dot notation, like:

LabSample.from_measurements(...)

# --- Class method example: alternate constructor ---

s1 = LabSample.from_measurements("PH-017", "pH", [6.98, 7.01, 6.99])
print(s1)
print("s1 measurements:", s1.measurements)
Output
sample id: PH-017, units: pH, sample size: 3

Why Class-Side Methods?

It can be unclear at first what should be an instance method versus a class method.
A good rule of thumb:

  • Instance methods define behaviour of a specific object (one LabSample).
  • Class methods define behaviour of the class as a whole (LabSample).

When should you use a class method?

Class methods usually fit one of these roles:

  • Instance creation (factory methods)
    Use a class method to create objects in a convenient way, hiding setup details.
    Example in LabSample: LabSample.from_measurements(...)

  • Answering questions about the class
    Return information that belongs to the class, often based on class variables.
    Example in LabSample: using the class variable LabSample.sample_count

  • Instance management
    Control how instances are created or accessed (e.g., limiting how many can exist).
    (We won’t implement “singleton” behaviour here, but this is a common use case.)

  • Examples / demonstrations
    Provide “example constructors” or sample objects to show how the class works (often for documentation).

  • Testing support
    Class methods can help build small, repeatable test scenarios (create an object, run an operation, check expected results).
    (Formal testing tools come later, but the idea is useful.)

Remark: If the behaviour is mainly about changing or using one object’s stored data (like a particular sample’s measurements), it belongs in an instance method.

Static Methods

A static method is another kind of method you can define inside a class.

Static methods are not tied to any specific object, and they are also not tied to the class.

  • They do not receive self (like instance methods).
  • They do not receive cls (like class methods).

In practice, a static method is like a normal “free-standing” function, but it lives inside the class as a way to keep related helper functions in one place.

How do you define a static method?

Use the decorator @staticmethod directly above the method definition.

In our LabSample class, we will introduce the static method is_valid_units:

  • It checks whether a units string looks reasonable.
  • It does not need to access self (an instance) or cls (the class).
@staticmethod
def is_valid_units(units):
    """
    Utility check: returns True if units look reasonable.
    This does not use self or cls.
    """
    if units is None or not isinstance(units, str):
        return False
    units = str(units).strip()
    return len(units) > 0

Remark: isinstance(units, str)

In Python, isinstance(x, T) asks: “Is x an instance (an object) of type T?” So isinstance(units, str) returns:

  • True if units is a string (like “cm”, “m/s”, “kg”)
  • False if units is not a string (like None, 5, 3.14, [“cm”], etc.)

This is a common way to do a type check before using string operations like .strip()

  • calling .strip() on a non-string would cause an error.
print(isinstance("cm", str))   # True
print(isinstance(10, str))     # False
print(isinstance(None, str))  # False
Output
True
False
False

Closing Remarks

  • Class methods and static methods are different in Python. In some languages, Class methods and static methods refer to the same thing.
  • Class methods do receive cls and are used for class-side behaviour.
  • Static methods receive neither cls nor self and act like helper functions stored on the class.
