Inheritance

Introduction

  • Inheritance is a core feature of Object-Oriented Programming (OOP).
  • It lets one class reuse data (attributes) and behaviour (methods) from another class.
  • In Python, inheritance helps you avoid duplicating code and makes it easier to maintain.

Inheritance means:

A new class can build on an existing class.

Example

Suppose we start with a Person:

  • attributes: name, age
  • method: birthday()

Now we want an Employee:

  • employees also have name, age, and birthday()
  • plus: id and calculate_pay()

We could copy/paste name, age, and birthday() into Employee but that causes problems:

  • it’s inefficient (duplicate work)
  • if you fix a bug in Person.birthday(), you might forget to fix the copied version in Employee

Fix: define shared behaviour once, reuse it everywhere.

Inheritance in a Class Hierarchy

Example hierarchy (conceptual)

  • Person (general)
    • Employee (more specific)
      • SalesPerson (even more specific)

Inheritance means:

  • Employee automatically gets everything from Person
  • SalesPerson automatically gets everything from Employee (and therefore from Person too)

Python syntax for inheritance

General pattern:

class SubClassName(BaseClassName):
    classbody
  • The base class goes in parentheses after the subclass name.
  • The subclass automatically inherits all attributes/methods from the base class.
class Person:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def birthday(self):
        print("Happy birthday you were", self.age)
        self.age += 1
        print("You are now", self.age)
class Employee(Person):
    def __init__(self, name, age, id):
        # Run Person's initializer first
        super().__init__(name, age)
        self.id = id

    def calculate_pay(self, hours_worked):
        rate_of_pay = 7.50
        if self.age >= 21:
            rate_of_pay += 2.50
        return hours_worked * rate_of_pay

What just happened in Employee?

class Employee(Person):
    def __init__(self, name, age, id):
        # Run Person's initializer first
        super().__init__(name, age)
        self.id = id

    def calculate_pay(self, hours_worked):

        if self.age >= 21:
            rate_of_pay += 2.50
        return hours_worked * rate_of_pay
  1. Employee(Person) means:
    • Employee inherits from Person.

  1. super().__init__(name, age) means:

    • Call the base-class (Person) constructor so name and age get set up properly.

    Convention:

    • put super().__init__(...) near the start of __init__
    • so base-class initialization happens before subclass-specific setup

  2. What each class has:

    A Person has:

    • attributes: name, age
    • methods: birthday()

    An Employee has:

    • attributes: name, age, id
    • methods: birthday(), calculate_pay(...)

  3. Inherited attributes are used normally:

    • employee.calculate_pay(40) can use self.age
    • even though age was defined in Person
    class Employee(Person):
  def __init__(self, name, age, id):
      # Run Person's initializer first

      self.id = id

Introducing SalesPerson Class

class SalesPerson(Employee):
    def __init__(self, name, age, id, region, sales):
        # Run Employee's initializer (which runs Person's too)
        super().__init__(name, age, id)
        self.region = region
        self.sales = sales

    def bonus(self):
        return self.sales * 0.5

What does SalesPerson inherit?

SalesPerson(Employee) means SalesPerson gets:

From Person:

  • name, age
  • birthday()

From Employee:

  • id
  • calculate_pay(...)

Plus its own:

  • region, sales
  • bonus()

So a SalesPerson has the most features because it sits lowest in the hierarchy.

print("Creating an instance of SalesPerson")
margaret = SalesPerson("Margaret Hamilton", 21, 4712, "USA", 30000.0)
margaret.birthday()
print("margaret.calculate_pay(40):", margaret.calculate_pay(40))
print("margaret.bonus():", margaret.bonus())
Output
Creating an instance of SalesPerson
Happy birthday you were 21
You are now 22
margaret.calculate_pay(40): 400.0
margaret.bonus(): 15000.0

Remarks:

  1. Creating subclasses does not change the base class.

    • Person does not gain an id, region, or sales.

  2. Capabilities depend on the class:

    • All three (Person, Employee, SalesPerson) have access to: birthday()
    • Only Employee, SalesPerson have access to: calculate_pay(...)
    • Only SalesPerson has access to: bonus()

  3. The Person <– Employee <– SalesPerson hierarchy demonstrates an “is-a” relationship: an Employee is a Person, and a SalesPerson is an Employee.

    Class hierarchies that follow an “is-a” relationship, where each subclass is a more specialized version of its parent class, are commonly used in object-oriented programming.

    In contrast, there is also a “has-a” relationship, where an object contains or owns another object as a part of itself through composition (a field/attribute). We will discuss “has-a” relationships later this semester.

Terminology Around Inheritance

We will wrap-up this short introduction to inheritance by turning our attention to common terms used in most OOP languages (including Python)

Class

  • A class defines:
    • data (attributes / fields)
    • behaviour (methods / functions that operate on that data)

Subclass (child / derived class)

  • A subclass is a class that inherits from another class.
  • Example: Employee might inherit from Person.
  • A subclass is still a normal class:
    • it can add new attributes/methods
    • it can override methods
  • Any class can have many subclasses.

Superclass (parent / base class)

  • A superclass is the class that another class inherits from.
  • Example: Person is the superclass of Employee.
  • In Python, a class can have one or more superclasses.

Single vs Multiple Inheritance

  • Single inheritance: a class inherits from exactly one superclass.
    • Example: Java only supports single inheritance for classes.
  • Multiple inheritance: a class can inherit from more than one superclass.
    • Python supports this (e.g., class C(A, B): ...)
    • We will discuss multiple inheritance later
