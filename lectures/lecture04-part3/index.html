Multiple Inheritance

What is multiple inheritance?

  • Multiple inheritance means a class can inherit from more than one superclass.
  • Python supports this (many languages restrict inheritance to one base class).

Example: ToyCar is both a Car and a Toy

Syntax

To inherit from more than one class, list base classes in parentheses:

class SubClassName(BaseClass1, BaseClass2, ..., BaseClassN):
    classbody

Remarks:

  • Base classes are separated by commas.
  • The order matters (we’ll see why below).
# Example: ToyCar inherits from both Car and Toy

class Car:
    def move(self):
        print("moving")

class Toy:
    def color(self):
        print("red")

class ToyCar(Car, Toy):
    """A Toy Car"""
    pass
tc = ToyCar()
tc.move()
tc.color()
Output
moving
red

What does the subclass ToyCar(Car, Toy) inherit?

ToyCar(Car, Toy) inherits:

  • attributes and methods from Car
  • attributes and methods from Toy
  • and (indirectly) from object (the root of all classes)

What if both Parents define the same method?

Suppose both Car and Toy define move().

class Car:
    def move(self):
        print("Car - move()")

class Toy:
    def move(self):
        print("Toy - move()")

class ToyCar(Car, Toy):
    """A Toy Car"""
    pass
# Create an instance of ToyCar
tc = ToyCar()

Calling tc.move()

Which move() should Python run?

  • Car.move()?
  • or Toy.move()?
tc.move()  # Which move() runs?
Output
Car - move()

This example highlights the kind of ambiguity that can arise in multiple inheritance, commonly referred to as the diamond problem.

To understand why this happens, we need to take a closer look at how Python decides which method to call when a class inherits from multiple parents.

Method Resolution Order (MRO)

MRO

Python uses a rule called the Method Resolution Order (MRO) to decide where to look

Method Resolution Order (MRO):

  1. Look in the class itself (ToyCar)
  2. Then look in its parent classes, left to right (first Car, then Toy)
  3. Keep going upward through ancestors until the method is found

So for:

class ToyCar(Car, Toy):

Python will look for move() in this order:

  • ToyCar
  • Car
  • Toy
  • object

That means Car.move() wins if both parents have move().

Order Matters

In multiple inheritance:

  • the order of base classes matters
  • because it changes the search order for methods with the same name
class Car:
    def move(self):
        print("Car - move()")

class Toy:
    def move(self):
        print("Toy - move()")

# class ToyCar(Car, Toy) older header
class ToyCar(Toy, Car):
    """A Toy Car"""
    pass
# Create an instance of ToyCar
tc = ToyCar()
tc.move() # Which move() runs?
Output
Toy - move()

Inspecting MRO

You can inspect Python’s method search order using the MRO:

class Car:
    def move(self):
        print("Car - move()")

class Toy:
    def move(self):
        print("Toy - move()")

class ToyCar1(Toy, Car):
    """A Toy Car"""
    pass

class ToyCar2(Car, Toy):
    """A Toy Car"""
    pass
#print("ToyCar1(Toy, Car) MRO:", ToyCar1.mro())
#print("ToyCar2(Car, Toy) MRO:", ToyCar2.mro())

print("ToyCar1(Toy, Car) MRO:", [cls.__name__ for cls in ToyCar1.mro()])
print("ToyCar2(Car, Toy) MRO:", [cls.__name__ for cls in ToyCar2.mro()])
Output
ToyCar1(Toy, Car) MRO: ['ToyCar1', 'Toy', 'Car', 'object']
ToyCar2(Car, Toy) MRO: ['ToyCar2', 'Car', 'Toy', 'object']

super() Revisited

super() does not mean “call my parent”.

It means:

“Call the next implementation of this method in the MRO.”

This is important as multiple inheritance can cause some harmful effects:

  • the same method (especially in a shared base class) can be executed more than once
  • side effects like updating counters, opening files, or mutating shared state can happen twice
  • some parent behaviour may be skipped entirely if methods are called manually

Using super() consistently lets Python follow the MRO and ensures each class in the hierarchy participates exactly once.

Final Remarks: Multiple Inheritance Warning

Creating Complexity with Multiple Inheritance

Multiple inheritance can look powerful because it lets one class mix features from several parents.

It can be useful - but it comes with a big warning:

Warning:

  • Multiple inheritance can create complex method search paths.
  • If two parents (or grandparents) define the same method name, it can be hard to predict which one will run.
  • Small changes higher up in the inheritance tree (like changing the order of parents) can cause surprising behaviour down below in classes you didn’t touch.

Remark: It’s not that Python gets confused - it’s that humans do.

What to Remember

  • Python follows a strict Method Resolution Order (MRO) to decide which method to use.
  • The order of base classes can change the behaviour of your program.
  • super() means: “Call the next implementation of this method in the MRO.”

Remark: We won’t go any deeper into Multiple Inheritance in this course, just treat it as an advanced tool that requires care.
