Exception Handling

What Is Exception Handling?

Exception handling is about where responsibility lives.

Often, the code that detects a problem:

  • cannot fix it, and
  • should not decide how to respond

Instead, the exception is passed upward to code that can respond.

This process is called exception handling.

Exception Handling (Adding Control Flow)

Exception handling causes Python to:

  • stop the current operation
  • abandon the current line of execution
  • search for code that knows how to respond

This is a controlled transfer of responsibility that can be controlled using the try-except construct.

try block

The try block indicates the code which is to be monitored for the exceptions listed in the except expressions.

except clause

The except clause to indicate what to do when certain classes of exception/error occur (e.g. resolve the problem or generate a warning message). There can be any number of except clauses in sequence checking for different types of error/exceptions.

The syntax for a try statement with an except clause is:

try:
    <code to monitor>
except <type of exception to monitor for>:
    <code to call if exception is found>

Example

Below is a code snippet that performs a simple calculation on some hard-coded user input:

user_input = "hello"
x = int(user_input)
print(100 / x)
Output
---------------------------------------------------------------------------
ValueError                                Traceback (most recent call last)
Cell In[3], line 2
      1 user_input = "hello"
----> 2 x = int(user_input)
      3 print(100 / x)

ValueError: invalid literal for int() with base 10: 'hello'

Remarks:

  • When int() is passed a non-numeric string (e.g., "Hello"), a ValueError exception is raised.
  • The ValueError halts the program and transfers responsibility to the programmer to decide how to respond.

Response: We will use exception handling to print a human-readable message.

user_input = "Hello"
# adding exception handling (try-except)
try:
    x = int(user_input)
    print(100 / x)
except ValueError:
    print("That was not a valid number.")
Output
That was not a valid number.

What Just Happened?

  • The int() function raised a ValueError

    • When Python evaluates int("Hello"), it cannot convert the non-numeric string into an integer.
    • As a result, int() raises a ValueError.

  • The exception was passed to the calling code

    • The error occurs inside int(), but int() does not handle it.
    • The exception propagates upward to the surrounding try block.

  • The matching handler responded

    • Python searches for an except clause that matches the exception type.
    • except ValueError: matches, so that handler executes and prints the message.

ZeroDivisionError: division by zero

Issue

The division / operator raised a ZeroDivisionError

Response

Add an additional except block to handle the ZeroDivisionError, extending the controlled transfer of responsibility.

user_input = 0

try:
    x = int(user_input)
    print(100 / x)
except ValueError:
    print("That was not a valid number.")
except ZeroDivisionError:
    print("Division by zero is not allowed.")
Output
Division by zero is not allowed.

try-except Contstruct Continued

There are two additional try-except contstruct clauses:

else clause.

This is an optional clause which will run if and only if no exception was thrown in the try block. It is useful for code that must be executed if the try clause does not raise an exception.

ﬁnally clause.

The optional ﬁnally clause runs after the try block exits (whether or not this is due to an exception being raised). You can use it to clean up any resources, close ﬁles, etc.

def program(input):
    try:
        x = int(input)
        result = 100 / x
    except ValueError:
        print("That was not a valid number.")
    except ZeroDivisionError:
        print("Division by zero is not allowed.")
    else:
        return result
    finally:
        print("End of Program")
user_input = 0
result = program(user_input)
print(result)
Output
Division by zero is not allowed.
End of Program
None
user_input = 20
result = program(user_input)
print(result)
Output
End of Program
5.0

Terminology

Exception Handling Terminology

You will see the following terms:

Exception:

A runtime signal that expectations were violated

Raise an exception:

Create a new exception

Handling an exception:

Responding to an exception

Handler:

Code that responds to a specific type of exception

Example

user_input = "Hello"

try:
    x = int(user_input)
    print(100 / x)
except ValueError:
    print("That was not a valid number.")

Exception:

The ValueError object that represents the runtime signal value error.

Raise the exception:

The moment int(user_input) fails and raises a ValueError (it creates/signals the exception).

Handling the exception:

What your program does in response: it prints "That was not a valid number." instead of haulting.

Handler:

The except ValueError: block (and its indented body). This is the specific code written to respond to a ValueError.

Type-Based

Handlers Are Type-Based

An except clause does not catch everything.

It catches:

  • a specific exception type
  • or any of its subclasses

    • except ArithmeticError:

Catching Broad Categories

Exception class

Exception represents a broad category of runtime violations.

Catching it means:

“I am willing to handle many kinds of failures in the same way.”

This can be useful, but it reduces precision.

user_input = 0.0

try:
    x = int(user_input)
    print(100 / x)
except Exception:
    print("opps ¯\\_(ツ)_/¯")
Output
opps ¯\_(ツ)_/¯

Remark:

  • This might not seem useful as we don’t get any useful information,
  • but it can be helpful when catching multiple exceptions

Multiple Handlers

If different violations require different responses, you can provide multiple except clauses.

Only one handler runs. The first matching one wins.

user_input = ["0", "10", "hello", ""]

for ui in user_input:
    try:
        print(f"User input = {ui} (type: {type(ui).__name__})")
        x = int(ui)              # could raise ValueError
        result = 100 / x         # could raise ZeroDivisionError
        print("Result:", result)
        print("-"*10)
    
    except ValueError:
        print("Please enter a whole number (like 3, 10, -2).")
        print("-"*10)
    
    except ZeroDivisionError:
        print("You entered 0, and division by zero is not allowed.")
        print("-"*10)
    
    except Exception:
        print("Something unexpected happened:")
        print("-"*10)

Handler Ordering Matters

Handlers must go:

  • from most specific
  • to most general

Why?

Because Python chooses the first matching handler.

A broad handler placed first would block all others.

user_input = ["0", "10", "hello", ""] 

for ui in user_input: 
    try:
        x = int(ui)      # could raise ValueError
        result = 100 / x         # could raise ZeroDivisionError
        print("Result:", result)

    except Exception: # Blocks all other exceptions
        print("Something unexpected happened:")

    except ValueError:
        print("Please enter a whole number (like 3, 10, -2).")

    except ZeroDivisionError:
        print("You entered 0, and division by zero is not allowed.")
Output
Something unexpected happened:
Result: 10.0
Something unexpected happened:
Something unexpected happened:

Final Remarks

Exception handling is not about fixing code.

It is about declaring responsibility.

Using except says:

“I understand this kind of failure, and I know how to respond.”

Accessing the Exception Object

Accessing the Exception Object

So far, we have handled exceptions by type only.

Sometimes, however, we want to know:

  • what specifically went wrong
  • why Python raised this exception

Python allows us to access the exception object itself.

The as Keyword

When catching an exception, you can optionally bind the exception object to a variable using as.

This gives you access to:

  • the exception message
  • contextual information about the failure
import traceback

user_input = "0"

try:
    x = int(user_input)
    result = 100/x
    print("Result:", result)
except ZeroDivisionError as e:
    print("type(e)         =", type(e).__name__)
    print("str(e)          =", str(e))
    print("e.args          =", e.args)
    print("e.__traceback__ =", e.__traceback__)

    print("\n--- traceback.print_exception ---")
    traceback.print_exception(type(e), e, e.__traceback__)
Output
type(e)         = ZeroDivisionError
str(e)          = division by zero
e.args          = ('division by zero',)
e.__traceback__ = <traceback object at 0x7a0e4846e7c0>

--- traceback.print_exception ---
Traceback (most recent call last):
  File "/tmp/ipykernel/2421386816.py", line 7, in <module>
    result = 100/x
             ~~~^~
ZeroDivisionError: division by zero

Remarks:

  • import traceback imports the traceback module, which provides tools for working with exception tracebacks.
    • traceback.print_exception(type(e), e, e.__traceback__) prints the full traceback programmatically.
  • Accessing the exception object allows you to:
    • display clearer error messages
    • log diagnostic information
    • decide how to respond based on details

Multiple Handlers, Optional Access

Each except clause can independently decide whether to:

  • bind the exception object
  • or ignore it

This choice is local to each handler.

        print("type: ", type(e))
        print("repr(e) = ", repr(e))
        print("-"*10)

Jumping to an Exception Handler

Jumping to an Exception Handler

When an exception is raised:

  • execution stops immediately
  • remaining statements are skipped
  • control is transferred to a handler

This is not optional behavior. It is how Python enforces broken expectations.

Key Rule

Once an exception is raised:

Nothing after that point runs.

Not in the function. Not in the calling code. Only the matching handler executes.

def my_function(x, y):
    print("my_function in")
    result = x / y
    print("my_function out")
    return result

Case 1: Expectations Are Met

Here, no exception is raised. Execution proceeds normally.

print("Starting")
try:
    print("Before my_function")
    my_function(6, 2)
    print("After my_function")
except ZeroDivisionError:
    print("oops")

print("Done")
Output
Starting
Before my_function
my_function in
my_function out
After my_function
Done

Observations: Output (No Exception)

  • Every line runs
  • The handler is skipped
  • Control flow is uninterrupted

Case 2: Expectations Are Violated

Now we violate an expectation: division by zero.

print("Starting")

try:
    print("Before my_function")
    my_function(6, 0)
    print("After my_function")
except ZeroDivisionError:
    print("oops")

print("Done")
Output
Starting
Before my_function
my_function in
oops
Done

Observations: Output (Exception Raised)

Notice what does not happen:

  • my_function out is never printed
  • After my_function is never printed

Execution jumps directly to the handler.

Raising Exceptions

Raising an Exception (Design View)

So far, we have seen Python raise exceptions automatically. But what if we want to raise an exception in our own code?

This can be accomplished by using the raise keyword:

raise <Exception/Error type to raise>()

Example: Forcing Expectations

def is_even(x):
    return x % 2 == 0

is_even(3.4)
Output
False

Remark:

Even though this runs without error, we (as the programmers) expect the user to pass an integer, not a float. We can enforce this expectation by explicitly raising an exception:

def is_even(x):
    if not isinstance(x, int):
        raise TypeError("Input must be an integer")
    return x % 2 == 0

is_even(3.4)

Handling a Raised Exception

Once raised, an exception behaves the same way as any built-in error.

Important Design Point

Raising an exception does not mean:

  • the code is “broken”
  • something unexpected happened

It means:

“This situation violates the contract of this function.”

Re-raising Exceptions

Sometimes you want to catch an exception to log, inspect, or clean up, but still allow it to propagate up the call stack.

This is done by re-raising the exception.

Why re-raise?

  • Preserve the original error for higher-level handling
  • Add logging or debugging information
  • Avoid silently swallowing errors

Key Idea

Use raise inside an except block to re-throw the same exception.

try:
    x = int("abc")
except ValueError as e:
    print("Conversion failed:", e)
    raise  # re-raises the same ValueError
Output
Conversion failed: invalid literal for int() with base 10: 'abc'
---------------------------------------------------------------------------
ValueError                                Traceback (most recent call last)
Cell In[27], line 2
      1 try:
----> 2     x = int("abc")
      3 except ValueError as e:
      4     print("Conversion failed:", e)

ValueError: invalid literal for int() with base 10: 'abc'

Important Notes

  • raise (with no argument) preserves the original traceback
  • Avoid catching exceptions unless you intend to handle or re-raise them
  • Swallowing exceptions can make debugging difficult
# BAD: silently swallowing the error
try:
    x = int("abc")
except ValueError:
    pass

# GOOD: log and re-raise
try:
    x = int("abc")
except ValueError as e:
    print("Error occurred:", e)
    raise

Object Representations

Introducing __repr__()

You already know __str__() gives a human-friendly string for an object.

For debugging purposes, we introduce __repr__():

  • A printable representation of an object
  • __repr__() is the developer-friendly string.
  • It is used for debugging and for showing objects inside containers (like lists).

Rule of thumb:

  • __str__() = “nice to read”
  • __repr__() = “useful for debugging”

In many cases, __repr__() looks like valid Python code that could recreate the object. (That’s a convention — not a strict rule.)

class Person:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def __str__(self):
        # Human-friendly (for print)
        return self.name + " is " + str(self.age)  # fix: cast age to string

    def __repr__(self):
        # Developer-friendly (for debugging)
        # Convention: show class name + field names + repr() of each value
        return f"Person(name={self.name!r}, age={self.age!r})"
p = Person("Alan Turing", 41)

print(p)         # uses __str__
print(str(p))    # uses __str__

print(repr(p))   # uses __repr__
Output
Alan Turing is 41
Alan Turing is 41
Person(name='Alan Turing', age=41)
people = [p, Person("Ada Lovelace", 36)]
print(people)    # list uses __repr__ for its elements
Output
[Person(name='Alan Turing', age=41), Person(name='Ada Lovelace', age=36)]

Remarks:

You get __str__() when you:

  • use print(obj)
  • use str(obj)
  • use an f-string like f"{obj}"

You get __repr__() when you:

  • type obj in the Python shell / notebook
  • call repr(obj)
  • put objects inside a list, dict, or other container (Python uses repr for the elements)

Key idea: __repr__() helps you debug

A good __repr__() makes it easy to answer:

  • “Which object is this?”
  • “What are its attribute values right now?”
  • “Does something look wrong with the data?”

This matters during exception handling because you often want to print objects right when something breaks.

# Example: Using repr() when debugging an exception

try:
    p = Person("Grace Hopper", "85")  # age is a string (this might be a bug)
    print("Debug object:", repr(p))   # show the internal state clearly
    print(p.age + 1)                 # TypeError: can't add int to str
except TypeError as e:
    print("Caught:", e)
    print("Object at time of error:", repr(p))
Output
Debug object: Person(name='Grace Hopper', age='85')
Caught: can only concatenate str (not "int") to str
Object at time of error: Person(name='Grace Hopper', age='85')

Adding Object Representation in f-strings: !r inside f-strings

In f-strings:

  • {value} uses str(value)
  • {value!r} uses repr(value)

That’s why __repr__() often uses !r:

  • strings show quotes (helpful!)
  • types are clearer during debugging
name = "Ada"
print(f"{name}")     # Ada                                  (str)
print(f"{name!r}")   # 'Ada'                                (repr)

p = Person("Alan Turing", 41)
print(f"{p}")        # Alan Turing is 41                    (str)
print(f"{p!r}")      # Person(name='Alan Turing', age=41)   (repr)
Output
Ada
'Ada'
Alan Turing is 41
Person(name='Alan Turing', age=41)
