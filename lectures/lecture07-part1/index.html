Introduction

Why Text I/O Matters

Up to now, most of our programs have interacted only with the user through the console.

Real programs rarely work this way.

Instead of:

  • asking the user to type data every time
  • printing results that disappear when the program ends

Programs often:

  • read input from text files
  • write output to text files

Text I/O allows programs to:

  • work with large amounts of data
  • store results permanently
  • communicate with other programs
  • run without direct user interaction

This lecture introduces how Python programs read and write text data using files.

From Console Programs to File-Driven Programs

So far, our programs have relied on:

  • input() to receive data
  • print() to display results

This works well for:

  • small examples
  • interactive programs
  • learning basic control flow

However, console-based input/output has limitations:

  • users must re-enter data every run
  • data is lost when the program ends
  • programs cannot easily process large datasets

File-driven programs solve these problems by:

  • reading input from text files
  • writing results to text files
  • separating data from code

In this lecture, we shift from: interactive programs –> data-driven programs

Understanding Text Files

What Is a Text File?

A text file is a file that stores data as characters.

Text files are:

  • human-readable
  • editable with simple text editors
  • commonly used for data, logs, and configuration

Examples of text files:

  • .txt
  • .csv
  • .log
  • .json (we will see this later)

Important idea:

  • A file’s extension is only a convention
  • What matters is how the data is stored and read

In Python, when we work with text files:

  • data is read as strings
  • data is written as strings
  • Python handles character encoding for us (talk more about this later)

Examples:

  • .txt (Plain Text)

    A simple text file with one piece of data per line.

    Alan Turing
Ada Lovelace
Tim Berners-Lee
Grace Hopper

  • .csv (Comma-Separated Values)

    Structured text data, often used for tables.

    name,age,city
Alan Turing,21,Maida Vale
Ada Lovelace,19,London
Tim Berners-Lee,22,London

  • .log (Log File)

    Text files used to record events over time.

    2026-02-07 10:15:32 INFO Program started
2026-02-07 10:15:33 WARNING Invalid input detected
2026-02-07 10:15:35 INFO Program finished

  • .json (JavaScript Object Notation)

    Structured text using key–value pairs.

    {
"name": "Alice",
"age": 21,
"enrolled": true
}

Text Files vs Binary Files

Not all files store data as readable text.

There are two broad categories of files:

  • Text files
  • Binary files

Text files:

  • store data as characters
  • are human-readable
  • are opened in text mode
  • examples: .txt, .csv, .log, .json

Binary files:

  • store raw bytes
  • are not human-readable
  • are opened in binary mode
  • examples: images, audio files, compiled programs

In this part of the lecture we focus on text I/O.

Later we will introduce Binary I/O

The File Lifecycle and Paths

The File Lifecycle: Open –> Read/Write –> Close

Working with a file usually follows the same 3-step lifecycle:

  1. Open the file

    • connect your program to a file on disk
    • choose how you want to use it (read / write / append)

  2. Read or Write

    • reading: bring text from the file into your program (as strings)
    • writing: send text from your program into the file

  3. Close the file

    • release the resource
    • ensure data is fully written
    • prevent bugs caused by “dangling” open files

Important: If you skip the close step:

  • data may not be saved correctly
  • you can waste system resources
  • later file operations may fail or behave strangely

Files are external resources - your program must manage them carefully.

File Paths and File Names

To open a file, Python needs to know where it is.

A file path tells the operating system how to locate a file.

Two common types of paths:

1) Relative paths

A path relative to your program’s current working directory.

Examples:

  • "data.txt"
  • "data/people.csv"
  • "logs/run.log"

Relative paths are useful when:

  • your project has folders (data/, logs/, output/)
  • you want your program to work on different computers

2) Absolute paths

A full path from the root of the file system.

Example (Linux):

  • "/home/ryan/project/data.txt"

Absolute paths are useful when:

  • you need an exact location
  • but they are less portable between computers

Important note:

  • “file not found” errors are often just path problems
  • always know what your current working directory is

pathlib module

Python also provides a module called pathlib that represents paths as objects.

This modulo is a modern, standard way to work with paths. Some of the advantages are:

  • it can make path handling cleaner and less error-prone
  • it works nicely across operating systems (Windows / macOS / Linux)
from pathlib import Path

# Relative path (relative to the current working directory)
rel_path = Path("data") / "people.txt"
print("Relative path:", rel_path)

# Current working directory (where relative paths start from)
cwd_path = Path.cwd()
print("CWD:", cwd_path)

# Convert the relative path into an absolute path
abs_path = rel_path.resolve()
print("Absolute path:", abs_path)
Output
Relative path: data/people.txt
CWD: /home/ryan/git/cpsc101/lectures/lecture07
Absolute path: /home/ryan/git/cpsc101/lectures/lecture07/data/people.txt

Remark: We will not dig any further on how to use this module, but it’s worth knowing that it exists.

Opening Files and File Modes

The open() Function

To work with a file, you first call:

open(path, mode)

  • path is a string naming the file (often a relative path)
  • mode is a string that controls how you will use the file

Some common modes are:

  • "r" - Read
  • "w" - Write
  • "a" - Append

Remark: Choosing the correct mode matters because it affects:

  • whether the file must exist
  • whether old data is preserved or destroyed
  • where new text will go at the end

We will look into the different modes in more details soon.

TextIOWrapper Object

When you call open(path, mode), Python creates a file object.

Internally, this is a TextIOWrapper object

This object:

  • represents a connection between your program and a file on disk
  • knows how the file may be used (read, write, append)
  • keeps track of a current position in the file (the file cursor)
  • provides methods like read(), write(), and close()

You should think of the file object as a handle, not the file itself.

Remarks:

  • the type of object (TextIOWrapper) is the same for read, write, and append
  • the mode controls behavior, not the object’s class
  • the file object (handler) doesn’t contain any data. It creates a connection to the file on disk

Opening a File in Read Mode ("r")

Read mode is used when:

  • the file already exists
  • you want to read its contents without changing them

Behavior:

  • file cursor starts at the beginning of file
  • writing is not allowed
  • file contents are preserved
path = "poem.txt"
file_handler = open(path, "r", encoding="utf-8")
print("file_handler is an instance of", type(file_handler).__name__)
print("repr(file_handler):", repr(file_handler))
print("Current cursor position:", file_handler.tell())
file_handler.close() # Always remember to close an open file when your done
Output
file_handler is an instance of TextIOWrapper
repr(file_handler): <_io.TextIOWrapper name='poem.txt' mode='r' encoding='utf-8'>
Current cursor position: 0

  • file_handler is an instance of TextIOWrapper

    • open() returned a text-mode file object
    • it behaves like a stream of characters
    • it supports methods like read(), readline(), iteration, and write() (depending on mode)

  • repr(file_handler): <_io.TextIOWrapper name='people.txt' mode='r' encoding='UTF-8'>

    • name='poem.txt' –> the file on disk this object is connected to
    • mode='r' –> the file was opened for reading only
    • encoding='UTF-8' –> bytes from disk are decoded into text using UTF-8
    • the _io. prefix indicates this is Python’s built-in I/O implementation

  • Current cursor position: 0

    • the file cursor (read position) is at the start of the file
    • the next read will begin at character position 0
    • reading moves the cursor forward automatically as data is consumed

Closing an Open Connection: close()

Closing an open connect to a file on disk does not deleted the file handler

path = "poem.txt"
file_handler = open(path, "r", encoding="utf-8")  # Creating a file handler in read mode "r"
file_handler.close()                              # Closing the open file

print(file_handler)                               # file_handle still exits after closing the open connection
Output
<_io.TextIOWrapper name='poem.txt' mode='r' encoding='utf-8'>
file_handler.read()             # rasies a ValueError since connection has been closed
Output
---------------------------------------------------------------------------
ValueError                                Traceback (most recent call last)
Cell In[4], line 1
----> 1 file_handler.read()             # rasies a ValueError since connection has been closed

ValueError: I/O operation on closed file.

Summary Tables of Modes (Including + Modes)

Table 1: File Modes and Descriptions

Mode Descriptions
"r" Read an existing file from the start.
"w" Create or overwrite a file and write from the start.
"a" Append to the end of a file (create it if missing).
"r+" Read and write an existing file, starting at the beginning.
"w+" Create or overwrite a file, then allow both reading and writing.
"a+" Append to a file and allow reading (writes always go to the end).

Table 2: File Modes and Technical Behavior

Mode File Must Exist Existing Data Cursor Starts Read Write
"r" Yes Preserved Beginning Yes No
"w" No Erased Beginning No Yes
"a" No Preserved End No Yes
"r+" Yes Preserved Beginning Yes Yes
"w+" No Erased Beginning Yes Yes
"a+" No Preserved End Yes Yes

Table 3: Available Read and Write Methods by Mode

Mode read() readline() Iteration (for line in f) write() writelines()
"r" Yes Yes Yes No No
"w" No No No Yes Yes
"a" No No No Yes Yes
"r+" Yes Yes Yes Yes Yes
"w+" Yes Yes Yes Yes Yes
"a+" Yes Yes Yes Yes Yes

Mode Guidelines

  • Use "r" when you only need to read.
  • Use "w" when you want to replace the file completely.
  • Use "a" when you want to add entries over time.
  • Use "+" modes only when you have a clear plan for:
    • cursor position (use seek(), tell() methods)
    • when you read vs when you write
    • whether overwriting or appending is intended

Remarks:

  • There are some classic “gotchas” that can occure when using the "+" modes. So use the "+" modes with care.
  • For the remaining of the lecture we will only be covering the basic modes:
    • "r", "w", "a"

Reading Files

Reading Text Files

When you read from a text file in Python:

  • the data is read from the disk (where the text file lives)
  • copied to memory as strings (where your program can now access)

Common reading patterns:

  1. Read the entire file at once (good for small files)
  2. Read one line at a time (good for large files)
  3. Loop over the file

In all cases, you:

  • open the file in "r" mode
  • read using a method (or iteration)
  • close the file

Common Reading Methods: read() and readline()

Python file objects provide multiple ways to read text.

read()

  • reads the entire remaining file into a single string
  • useful for small files
  • can be memory-heavy for large files

readline()

  • reads one line (up to and including the newline, if present)
  • useful when you want to control reading step-by-step
  • returns an empty string "" when you reach the end of the file

Remark:

  • Both methods return strings
  • Newline characters ("\n") are part of what you read
# --------------------------------- #
# Demo: read() reads the whole file #
# --------------------------------- #

fh = open("poem.txt", "r", encoding="utf-8")
contents = fh.read()
fh.close()

print(contents)
Output
*-------------*
“Love is binary,
twofold. You do or you don’t.
And programming? One.”
By Emily T.
*-------------*
# ----------------------------------------- #
# Demo: readline() reads one line at a time #
# ----------------------------------------- #

fh = open("poem.txt", "r", encoding="utf-8")

print(f"cursor position: {fh.tell()}\n") # tell() returns the cursor position

line1 = fh.readline()
print(f"Call readline() - Line 1: {line1}", end="")
print(f"cursor position: {fh.tell()}\n")

line2 = fh.readline()
print(f"Call readline() - Line 2: {line2}", end="")
print(f"cursor position: {fh.tell()}\n")

line3 = fh.readline()
print(f"Call readline() - Line 3: {line3}", end="")
print(f"cursor position: {fh.tell()}\n")

fh.close()
Output
cursor position: 0

Call readline() - Line 1: *-------------*
cursor position: 16

Call readline() - Line 2: “Love is binary,
cursor position: 35

Call readline() - Line 3: twofold. You do or you don’t.
cursor position: 67

Moving the cursor with seek()

You can also control the cursor position using the seek() method of the TextIOWrapper class:

# --------------------------------------------- #
# Demo: Using seek() to control cursor position #
# --------------------------------------------- #

fh = open("poem.txt", "r", encoding="utf-8")

print(f"cursor position: {fh.tell()}\n") # tell() returns the cursor position

line1 = fh.readline()
print(f"Call readline() - Line 1: {line1}", end="")
print(f"cursor position: {fh.tell()}\n")

cursor_pos = fh.tell()  # saving the cursor position (beginning of second line)
line2 = fh.readline()
print(f"Call readline() - Line 2: {line2}", end="")
print(f"cursor position: {fh.tell()}\n")

fh.seek(cursor_pos)     # setting cursor position by at the beginning of line 2
line2 = fh.readline()   # reading line two a second time
print(f"Call readline() - Line 2: {line2}", end="")
print(f"cursor position: {fh.tell()}\n")

fh.close()
Output
cursor position: 0

Call readline() - Line 1: *-------------*
cursor position: 16

Call readline() - Line 2: “Love is binary,
cursor position: 35

Call readline() - Line 2: “Love is binary,
cursor position: 35

Iterating Over a Text File

In Python, a file object is iterable.

This means:

  • you can loop directly over a file handle
  • each iteration gives you one line at a time
  • this is the most common and Pythonic way to read text files

Benefits of iteration:

  • simple syntax
  • memory-efficient (one line at a time)
  • works well for large files

Important detail:

  • each line includes the newline character "\n" at the end
  • you often need to clean or strip the line before processing
# ---------------------------------------- #
# Demo: iterating over a file line by line #
# ---------------------------------------- #

fh = open("poem.txt", "r", encoding="utf-8")

for line in fh:
    print(line)

fh.close()
Output
*-------------*

“Love is binary,

twofold. You do or you don’t.

And programming? One.”

By Emily T.

*-------------*
# ------------------------------ --- #
# Demo: stripping newline characters #
# ------------------------------ --- #

fh = open("poem.txt", "r", encoding="utf-8")

for line in fh:
    cleaned_line = line.strip() # cleaning up '\n'
    print(cleaned_line)

fh.close()
Output
*-------------*
“Love is binary,
twofold. You do or you don’t.
And programming? One.”
By Emily T.
*-------------*

Parsing Date

When you read from a text file, Python gives you strings.

That means your program must decide:

  • what each line means
  • how to break it into pieces (if needed)
  • how to convert pieces into the right types (int, float, etc.)

In Python, parsing is usually done with:

  • string methods (like split, strip)
  • type conversion functions (like int, float)
  • your own validation checks

Remark: Text I/O is easy. Interpreting the text correctly is the real work.

# Demo: reading lines and "parsing" basic information from them

fh = open("poem.txt", "r", encoding="utf-8")
print(fh.read())

fh.seek(0) # move pointer back to beginning
Output
*-------------*
“Love is binary,
twofold. You do or you don’t.
And programming? One.”
By Emily T.
*-------------*
0
for idx, line in enumerate(fh):
    #print(line)
    line = line.strip()

    # Skip empty lines
    if line == "" or ("*" in line):
        continue

    # Example parsing idea: count words in each line
    words = line.split()
    print(f"Line {idx+1} Word count:", len(words))

fh.close()
Output
Line 2 Word count: 3
Line 3 Word count: 6
Line 4 Word count: 3
Line 5 Word count: 3

Remark:

for idx, item in enumerate(<iterable>) lets you loop over an iterable and keep track of the index. In term of our file handle fh, we can loop over the lines and keep track of line numbers.

  • idx is the line index (starting at 0 by default)
  • line is the current line from the file

Since idx starts at 0, the line number is idx + 1 (f"Line {idx+1} Word count:") (You can also write enumerate(f, start=1) to start counting at 1.)

Writing Files

Writing Text Files

Writing to a text file means sending strings from your program (in memory) into a file (to disk).

Common reasons to write text files:

  • save results (so they persist after the program ends)
  • generate reports
  • create logs (record what happened)
  • export data for other programs

Basic work flow:

  1. open the file in a writing mode
  2. write strings to the file
  3. close the file

Overwriting vs Appending Data

When writing text files, two modes are easy to confuse:

"w" Write mode (overwrites)

  • starts writing at the beginning of the file
  • erases existing contents
  • good for “generate a fresh output file”

"a" Append mode (adds to end)

  • keeps existing contents
  • writes new text at the end
  • good for logs and “add one more record”

Rule of thumb:

  • Use "w" when you want a clean restart
  • Use "a" when you want to keep history

Common Writing Methods: write() and writelines()

Python file objects provide multiple ways to write text.

write()

  • writes a single string to the file at the current file cursor position
  • returns the number of characters written
  • does not add a newline automatically
  • you must include "\n" yourself if you want line breaks

writelines()

  • writes a sequence of strings (e.g., list of strings) to the file
  • writes them exactly as given
  • does not add newlines automatically between items
  • returns None

Key idea:

  • Both methods expect strings
  • Newline characters ("\n") are part of what you write (you must add them)

Demo: Writing to file in ‘w’ mode

# write(): single string
fh = open("poem2.txt", "w", encoding="utf-8")
fh.write("*  *  *  *  *\n")
fh.write("Type, type, type away\n")
fh.write("Compile. Run. Hip hip hooray!\n")
fh.write("No error today!”\n")
fh.write("By Samantha W.\n")
fh.write("*  *  *  *  *\n")
fh.close()

# Read back the file to see the result
fh = open("poem2.txt", "r", encoding="utf-8")
print(fh.read())
fh.close()
Output
*  *  *  *  *
Type, type, type away
Compile. Run. Hip hip hooray!
No error today!”
By Samantha W.
*  *  *  *  *
# writelines(): many strings at once
new_poem = [
    "Overwriting file with new poem:\n"
    "*  *  *  *  *\n",
    "The modem humming.\n", 
    "Code rapidly compiling.\n", 
    "Click. Perfect success.\n",
    "By Stephanie S.\n",
    "*  *  *  *  *\n"
    ]

fh = open("poem2.txt", "w") # Overwrites the contents of "poem2.txt"
fh.writelines(new_poem)     # writes each string exactly as provided
fh.close()

# Read back the file to see the result
