Files as Resources and Cleanup

Files as External Resources

A file is not just “data in your program”.

A file is an external resource managed by the operating system.

When you open a file, your program is asking the OS for:

  • permission to access it
  • a connection (a file handle)
  • buffering and system-level bookkeeping

Because files are external resources:

  • access can fail (missing file, permissions, locked file)
  • you must release them when you’re done
  • leaving files open can cause bugs and resource leaks

Why Files Must Be Closed

When you open a file, your program gets a connection to an external resource.

Closing a file is important because it:

  • releases the resource back to the operating system
  • flushes buffered data so writes actually reach the disk
  • prevents issues like “too many open files”
  • avoids file locks or access problems in other programs

What can go wrong if you forget to close?

  • data may not be fully written
  • the file may remain “in use”
  • your program may leak resources over time

In short: Open files create responsibilities — close them when you’re done.

Automatic Resource Management

Automatic Cleanup: The Idea Behind Context Managers

Because forgetting to close files is so common, Python provides a safer pattern: automatic cleanup.

A context manager is a tool that:

  • sets something up
  • guarantees cleanup afterward
  • even if an error happens in the middle

For files, cleanup means:

  • closing the file handle
  • flushing any buffered output

Python’s with statement uses a context manager to guarantee:

  • the file is closed automatically when the block ends

A First Look at with (Automatic File Closing)

The with statement is Python’s standard way to work with files safely.

Pattern:

  • open the file using with
  • do your reading or writing inside the block
  • when the block ends, Python automatically closes the file

Why this is better than manual open() / close():

  • you cannot “forget” to close the file
  • the file is closed even if an exception occurs
  • the code is shorter and clearer

Instead of this:

file_handle = open("output.txt", "w")
file_handle.write("Hello, file!\n")
file_handle.write("This file will be closed automatically.\n")
file_handle.close()

Use with:

# Writing with `with` (file closes automatically)

with open("output.txt", "w") as fh:
    fh.write("Hello, file!\n")
    fh.write("This file will be closed automatically.\n")
# Reading with `with` (file closes automatically)

with open("output.txt", "r", encoding="utf-8") as fh:
    contents = fh.read()

print(contents)
Output
Hello, file!
This file will be closed automatically.

File Errors

What Can Go Wrong with Text I/O?

Common categories of problems:

  • the file does not exist
  • the file exists but cannot be accessed
  • the file contents are not what you expect
  • the file operation is interrupted

Remarks:

  • these are runtime problems
  • your code may be syntactically correct and still fail

Common File-Related Runtime Errors

Some common exceptions you may encounter:

  • FileNotFoundError
  • PermissionError
  • IsADirectoryError
  • IOError / OSError

Exception Handling and File I/O (with with)

The with statement:

  • ensures the file is always closed
  • even if an exception occurs

Exception handling:

  • deals with what to do when something goes wrong
# Handling FileNotFoundError
try:
    with open("missing_file.txt", "r") as fh:
        contents = fh.read()
except FileNotFoundError as err:
    print("Error - file not found:", err.filename)

Output:

Error - file not found: missing_file.txt
# Handling FileNotFoundError and PermissionError
try:
    with open("/root/secret.txt", "r") as fh:
        data = fh.read()
except FileNotFoundError as err:
    print("File does not exist:", err.filename)
except PermissionError as err:
    print("Permission denied:", err.filename)

Output:

Permission denied: /root/secret.txt

Defensive Thinking

Bad Data Is Still Data

Successfully opening a file does NOT guarantee the data is usable.

Examples of bad data:

  • missing fields
  • extra or missing delimiters
  • unexpected values
  • incorrect formats
# Expected format: name,age
line = "Alice,twenty\n"

Remark:

  • file errors and data errors are different problems

Why Bad Data Is Dangerous

Bad data:

  • does not automatically raise exceptions
  • flows quietly through your program
  • produces incorrect results without warning

Example: Silent Failure

Consider the text file registry.txt of name and ages:

Alice,41
Bob,19
Charlie21
Dina,
Evan,twenty
Fatima,33,extra

Gabe,27

Lets naively count the number of people in the registry file:

# Naive counter: silently wrong
count = 0

with open("registry.txt", "r") as fh:
    for line in fh:
        count += 1

print("Registered people:", count)
Output
Registered people: 8

What went wrong?

We see that there some bad data in the registry file:

Alice,41          # good
Bob,19            # good
Charlie21         # bad: missing comma
Dina,             # bad: missing age
Evan,twenty       # bad: age not an int
Fatima,33,extra   # bad: too many fields
                  # bad: blank line
Gabe,27\n"        # good

The program actually counted:

  • good records
  • bad records
  • anything that looks like a line

So the program “works” in the sense that it runs and prints a result, but the result is not trustworthy.

This is a silent failure:

  • no traceback
  • no error message
  • incorrect answer

Defensive Programming with Files

Defensive programming means:

  • checking assumptions
  • validating input data
  • handling failure paths intentionally

Goals:

  • keep the program in a valid state
  • report errors clearly
  • avoid hidden bugs

Back to registry.txt

Lets revist our previous example of counting the number of people in registry.txt. This time we’ll take a defensive programming approach

# Count only VALID records in the format: name,age
valid_count = 0

with open("registry.txt", "r") as fh:
    # Read the file one line at a time
    for line in fh:
        # Remove trailing newline and surrounding whitespace
        line = line.strip()

        # Skip blank lines (not a person record)
        if line == "":
            continue

        # Split on commas — we expect EXACTLY two fields: name and age
        parts = line.split(",")
        if len(parts) != 2:
            # Examples: "Charlie23" or "Fatima,33,extra" --> invalid format
            continue

        # Clean up spaces around each field
        name, age_text = parts[0].strip(), parts[1].strip()

        # Name must not be empty (e.g., ",41" would be invalid)
        if name == "":
            continue

        # Age must be an integer (e.g., "twenty" is invalid)
        try:
            int(age_text)
        except ValueError:
            continue

        # If we reached here, the record passed all checks → count it
        valid_count += 1

print("Valid registered people:", valid_count)
Output
Valid registered people: 3
