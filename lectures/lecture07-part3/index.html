Motivation

Why Binary I/O?

So far, we have only worked with text input and output:

  • Reading text files
  • Writing text files
  • Printing data in a human-readable format

However, many real-world files are not text:

  • Images
  • Audio and video files
  • PDFs
  • Program data saved to disk

To work with these files, we need Binary I/O.

All Files Are Bytes

At the lowest level:

  • Every file is stored as a sequence of bytes
  • A byte is a number from 0 to 255
    • 1 byte is 8 bits. Range: 0=0000000020 = 0000~0000_2, 255=111111112255 = 1111~1111_2
  • Bytes are often shown in hex because each byte maps exactly to two hex digits, making values easy to read and compare.
    • Hex (base-16) uses digits 0–9 and letters A–F
    • Example: 'ABC' = \x41\x42\x43

The operating system does not know:

  • which files are “text”
  • which files are “binary”

That distinction is made by programs, not by the file system (Look up - file signatures, commonly known as “magic numbers” or “magic bytes” for more detail).

Working with Bytes in Python

From Text to Bytes: What Changes?

With text files, you worked with:

  • str
  • characters
  • encodings handled automatically
    • bytes to characters: encoding='UTF-8'

With binary files, you work with:

  • bytes
  • raw numeric values (0–255)
  • no encoding
  • the modes differ:
    • 'rb' — read bytes
    • 'wb' — write bytes (overwrite file)
    • 'ab' — append bytes

The file methods are the same:

  • read(), readlines()
  • write(), writelines()

What changes is the type of file handler and data.

# Creating a BufferReader file handler
with open("starry_night_van_gogh.jpg", "rb") as fh:
    data = fh.readline()

print("File Handle fh type:", type(fh).__name__)
print("Data type:", type(data).__name__)

# Creating a TextIOWrapper file handler
with open("poem.txt", "r") as fh:
    data = fh.readline()

print("File Handle fh type:", type(fh).__name__)
print("Data type:", type(data).__name__)
Output
File Handle fh type: BufferedReader
Data type: bytes
File Handle fh type: TextIOWrapper
Data type: str

The bytes Type

bytes is:

  • an immutable sequence of integers (0–255)
  • often displayed as b'...'

Key properties:

  • indexable
  • sliceable
  • not editable

This makes bytes ideal for:

  • reading from files
  • representing raw file contents

The bytearray Type

bytearray is:

  • a mutable sequence of integers (0–255)

This makes it useful when:

  • you need to modify data in place
  • you are building or editing binary data

For many file operations:

  • bytes is enough
  • bytearray is optional

Remarks:

  • use bytes for reading and writing files
  • use bytearray only when mutation is required
# bytes: immutable
data = bytes([65, 66, 67])   # ASCII values for A, B, C
print("data:", data)
print("type:", type(data).__name__)

try:
    print("\nTrying to mutate data")
    data[0] = 97  # will raise TypeError
except TypeError as err:
    print(err)

# bytearray: mutable
buf = bytearray([65, 66, 67])
print("\n------------------------")
print("buf:", buf)
print("type:", type(buf).__name__)

buf[0] = 97     # change 'A' to 'a'
buf[1] = 98     # change 'B' to 'b'
buf[2] = 99     # change 'C' to 'c'
print("\nMutation Allowed")
print("buf:", buf)
Output
data: b'ABC'
type: bytes

Trying to mutate data
'bytes' object does not support item assignment

------------------------
buf: bytearray(b'ABC')
type: bytearray

Mutation Allowed
buf: bytearray(b'abc')

Reading and Writing Binary Files

Reading Binary Files

Reading a binary file works just like text I/O, except the data you receive is bytes.

You still use:

  • read()
  • read(n)

But now:

  • the result is a bytes object
  • not a str

Reading a Fixed Number of Bytes

read(n):

  • attempts to read up to n bytes
  • may return fewer than n bytes
  • returns b"" at end of file

Recall our poem.txt file:

*-------------*\n
“Love is binary,\n
twofold. You do or you don’t.\n
And programming? One.”\n
By Emily T.\n
*-------------*

Lets read the first 100 bytes of this file:

with open("poem.txt", "rb") as fh:
    print("Reading the first 100 bytes:\n")
    print(fh.read(100),"\n")                        # reading the first 100 bytes
    
    fh.seek(0)                                      # setting the cursor position back to beginning of file
    print("Reading the first 100 bytes as hex:\n")                          
    print(fh.read(100).hex(' '))                    # reading the first 100 bytes as hex
Output

Writing Binary Files

Writing binary data also looks familiar:

  • use write(...)
  • pass in a bytes object

Key rule:

  • you must write bytes, not strings
# Write some raw bytes
with open("data.bin", "wb") as fh:
    fh.write(bytes([10, 20, 30, 40, 50]))

# Read the bytes back
with open("data.bin", "rb") as fh:
    data = fh.read()

print(data)
print(data.hex(' '))
print(list(data))
Output
b'\n\x14\x1e(2'
0a 14 1e 28 32
[10, 20, 30, 40, 50]

End-of-File (EOF) in Binary I/O

In text mode:

  • EOF is often checked using an empty string ""

In binary mode:

  • EOF is signaled by empty bytes: b""

This is critical for writing read loops. This will become more apparent in the next section.

Efficient Binary I/O (Chunks and Buffers)

Reading Binary Files in Chunks

For small files, you can do:

  • data = f.read() (read the entire file)

But for large files, that is risky:

  • it can use too much RAM
  • it can slow down your program
  • it can crash your program on very large files

Instead, we usually read a fixed-size chunk at a time.

The Chunking Pattern

The standard pattern is:

  1. read a chunk of bytes
  2. if the chunk is empty (b""), stop (EOF)
  3. otherwise process it (or write it) and repeat

This pattern is the foundation of:

  • file copy tools
  • file splitting tools
  • streaming large data safely

Reading with Fixed-Size Buffers

A “buffer” is just a chunk of bytes you reuse.

Common buffer sizes:

  • 4096 bytes (4 KB)
  • 8192 bytes (8 KB)
  • 65536 bytes (64 KB)

We pick a buffer size to:

  • reduce the number of read/write operations
  • avoid loading the full file into memory

Example: Chunked Read Loop

This example reads the file ./starry_night_van_gogh.jpg in chunks and counts total bytes, without ever loading the entire file at once.

BUFFER_SIZE = 4096

total = 0
with open("starry_night_van_gogh.jpg", "rb") as fh:
    while True:
        chunk = fh.read(BUFFER_SIZE)
        if chunk == b"":        # EOF
            break
        total += len(chunk)

print("Total bytes read:", total)
Output
Total bytes read: 348961
