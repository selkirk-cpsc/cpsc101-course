Standard Streams

Streams

A stream is a flow of data from a source to a destination.

Think “pipe”:

  • data arrives in order
  • you process it as it comes
  • you usually don’t control where it ultimately goes

Three Standard Streams

Python programs always have access to three “standard” streams:

  • Standard input: where input comes from (usually the keyboard)
    • input() –> reads from standard input
  • Standard output: where normal output goes (usually the console)
    • print() –> writes to standard output
  • Standard error: where error messages can go (usually the console)

In Python, these streams are accessible through the sys module:

  • sys.stdin (input stream)
  • sys.stdout (output stream)
  • sys.stderr (error/output stream)

stdout vs stderr

Programs often produce two kinds of output:

  • Results (the data the program is meant to produce)
  • Diagnostics (warnings, errors, progress messages)

Python provides two separate output streams so they don’t get mixed:

  • stdout (sys.stdout) –> results / normal output
  • stderr (sys.stderr) –> diagnostics / error messages

Why keep them separate?

  • so results can be saved or piped cleanly
  • while warnings/errors still reach the user

Writing to stdout and stderr

By default, print() writes to stdout. But you can redirect the output to any file/stream:

print(..., file = ... )

To write to stderr set file=sys.stderr:

print(..., file=sys.stderr)
import sys

print("RESULT: average=17.3")                               # writes to stdout
print("WARNING: missing values found", file=sys.stderr)     # writes to stderr
Output
RESULT: average=17.3
WARNING: missing values found

When to Write to stderr

A good time to write to standard error (stderr) is when your program is producing “real output” that someone might want to save or pipe elsewhere, but you still want to show warnings / progress / problems to the user.

Important Clarification: You Don’t “Read From stderr”

sys.stderr is an output stream. It’s meant for writing diagnostic messages, not for program input.

Normally:

  • programs write to stderr
  • humans or tools observe stderr (console, logs, etc.)

Averages from a Stream (stdout vs stderr)

In this demo, we’ll treat a text file as a stream of data.

Each run will:

  • generate a stream of values (one per line)
  • include some bad data (non-numeric lines)
  • process the stream line by line

Goals:

  • compute a meaningful result (the average)
  • report problems without corrupting the result
  • use output streams correctly
