Introduction

What Is Recursion?

Recursion is a method of solving problems that works by:

  • Breaking a problem into smaller subproblems
  • Solving those smaller subproblems in the same way
  • Continuing this process until the problem becomes simple enough to solve directly

Eventually, the problem becomes trivial, meaning it can be solved without further decomposition.

Example Problem: Sum of a List of Numbers

Let’s begin with a problem you already know how to solve.

Problem:
Compute the sum of a list of numbers.

Example list:

[1, 3, 5, 7, 9]

Before introducing recursion, we will first review the iterative solution.

Iterative Solution

The most common way to compute the sum of a list is by using a loop and an accumulator variable.

An accumulator keeps a running total as we iterate through the list.

def listsum(numList):
    theSum = 0
    for i in numList:
        theSum = theSum + i
    return theSum

print(listsum([1,3,5,7,9]))
Output
25

A Thought Experiment

Now pretend that Python does not have loops.

No for loops
No while loops

How could we compute the sum of a list?

To answer this question, it helps to think like a mathematician.

Addition as a Function of Two Numbers

In mathematics, addition takes two numbers.

So instead of thinking of adding a whole list, we can rewrite the list as a sequence of pairwise additions.

For example:

((((1 + 3) + 5) + 7) + 9)

Or written the other way:

(1 + (3 + (5 + (7 + 9))))

Solving from the Innermost Expression

Notice that the innermost parentheses are easy to compute:

(7 + 9)

We can simplify step by step.

total = (1 + (3 + (5 + (7 + 9))))
    total = (1 + (3 + (5 + 16)))
        total = (1 + (3 + 21))
            total = (1 + 24)
                total = 25

Key Idea

Each step simplifies the expression by solving a smaller problem.

Eventually the problem becomes so small that it can be solved directly.

This is the central idea behind recursion.

Rewriting the Problem Recursively

Let’s describe the sum of a list in terms of smaller lists.

Suppose we have a list:

numList

We can say:

The sum of the list equals first element (numList[0]) + sum of the rest of the list (numList[1:])

Mathematically:

listSum(numList) = first(numList) + listSum(rest(numList))

Where:

  • first(numList) = the first element of the list (numList[0])
  • rest(numList) = everything except the first element (numList[1:])

Recursive Implementation

def listsum(numList):
    if len(numList) == 1:
        return numList[0]
    else:
        return numList[0] + listsum(numList[1:])

print(listsum([1,3,5,7,9]))
Output
25

Parts of Recursive Functions

Important Parts of the Recursive Function

There are two crucial components of the recursive function listsum:

def listsum(numList):
    if len(numList) == 1:
        return numList[0]
    else:
        return numList[0] + listsum(numList[1:])

print(listsum([1,3,5,7,9]))

1. Base Case

    if len(numList) == 1:

This is the escape clause.

If the list contains only one number, the sum is simply that number.

Without this condition, the recursion would never stop.

2. Recursive Call

    return numList[0] + listsum(numList[1:])

The function calls itself on a smaller list.

Each call reduces the size of the problem by removing the first element.

Recursive Call Sequence

If we call:

    listsum([1,3,5,7,9])

Python performs the following recursive calls:

Reaching the Base Case

Eventually we reach:

    listsum([9])

This triggers the base case:

    return 9

Recursive Returns (Working Backward)

Once the base case is reached, the results propagate back up the call stack (more on this later).

Key Takeaway

Recursive algorithms work by:

  1. Breaking the problem into smaller problems
  2. Solving the smallest problem directly (base case)
  3. Combining the results as the recursion returns

This process continues until the original problem is solved.

The Three Laws of Recursion

The Three Laws of Recursion

All recursive algorithms must follow three fundamental rules.

These rules are often called The Three Laws of Recursion.

  1. A recursive algorithm must have a base case.
  2. A recursive algorithm must change its state and move toward the base case.
  3. A recursive algorithm must call itself recursively.

If any of these laws are violated, the recursion will not work correctly.

Law 1: The Base Case

A base case is the condition that allows the recursion to stop.

It represents the simplest version of the problem, which can be solved directly without further recursion.

Without a base case, the recursive function would call itself forever, leading to infinite recursion.

Example: Base Case in listsum

In the listsum algorithm, the base case occurs when the list has only one element.

At that point, the sum of the list is simply that element.

    if len(numList) == 1:
        return numList[0]

This condition allows the recursion to terminate.

Law 2: Move Toward the Base Case

Each recursive call must make progress toward the base case.

This means the algorithm must change its state in some way.

Usually, the problem becomes smaller with each recursive call.

What Does “Change of State” Mean?

A change of state means modifying the data used by the algorithm so that the next recursive call works on a simpler problem.

If the problem does not get smaller, the recursion will never reach the base case.

Example: Reducing the List

In the listsum function, the problem is reduced by shortening the list.

Each recursive call removes the first element.

    return numList[0] + listsum(numList[1:])

Original list:

    [1, 3, 5, 7, 9]

Recursive calls operate on:

    [3, 5, 7, 9]  
    [5, 7, 9]  
    [7, 9]  
    [9]

Eventually we reach the base case.

Law 3: The Function Must Call Itself

The final law is simple:

A recursive algorithm must call itself.

This is what makes recursion different from ordinary functions.

    return numList[0] + listsum(numList[1:])

Here the function listsum calls itself with a smaller list.

This is the defining feature of recursion.

Why Recursion Actually Works

The logic of recursion is not circular.

Instead, recursion works because:

  1. Each call solves a smaller problem
  2. Eventually we reach a base case
  3. The results are then combined as the calls return

This creates an elegant way of solving problems by reducing them step-by-step.

Designing Recursive Algorithms

When writing a recursive function, always check the three laws:

  1. Base case — When does the recursion stop?
  2. Progress toward base case — How does the problem get smaller?
  3. Recursive call — Where does the function call itself?

Self Check Question 1

How many recursive calls are made when computing:

listsum([2,4,6,8,10])

A. 6
B. 5
C. 4
D. 3

Answer

Correct answer: C. 4

Explanation:

listsum([2,4,6,8,10])  # Original fuction call (no recursive call)
    listsum([4,6,8,10])     # 1st call
        listsum([6,8,10])       # 2nd call
            listsum([8,10])         # 3rd call
                listsum([10])           # 4th call (base case)

The last call is the base case, so there are 4 recursive calls before reaching it.

Self Check Question 2

Suppose you write a recursive function to compute the factorial of a number.

$\mathrm{fact}(n) = n \times (n-1) \times (n-2) \times \ldots $

The factorial of zero is defined as:

0!=10! = 1

What would be the most appropriate base case?

A. n == 0
B. n == 1
C. n >= 0
D. n <= 1

Answer

Correct answer: A. n == 0

Because factorial is defined mathematically as:

0!=10! = 1

This provides the natural stopping point for the recursion.

def fact(n):
    if n == 0:
        return 1
    else:
        return n * fact(n - 1)

Recursion and the Call Stack

The Call Stack

To understand recursion, we need to understand an important concept:

The Call Stack

The call stack is a region of memory used by the program to store information about active function calls. Every time a function is called, Python places a new stack frame onto this stack.

Each stack frame contains information such as:

  • the function’s parameters
  • its local variables
  • the current position in the code
  • the return address (where execution should continue after the function returns)

Behaviour

The call stack has the following behaviour:

  • New function calls are pushed onto the stack
  • When a function finishes, its frame is popped off the stack, and control returns to the previous function.

Because frames are removed in the reverse order they were added, the call stack follows the rule:

Last In, First Out (LIFO)

Example Recursive Sum

Recall our recursive list sum function.

def listsum(numList):
    if len(numList) == 1:
        return numList[0]
    else:
        return numList[0] + listsum(numList[1:])

listsum([1,3,5,7]) # Calling our recursive function

Remarks:

  • The most recent call is always on top of the stack.
  • Once the base case is reached (listsum[1]), the recursion begins to unwind
  • The call stack eventually empties and the final result is returned. This process of returning results upward is called: stack unwinding

Remarks

Recursion works because the runtime system automatically manages a stack of function calls.

This implicit stack is what allows recursive algorithms to:

  • break problems into smaller pieces
  • solve them independently
  • combine the results as the stack unwinds

Call Stack Overflow

RecursionError Exception

Understanding the call stack explains why recursion works:

  1. Each recursive call has its own frame
  2. The stack remembers where to return
  3. Results propagate back as the stack unwinds

Warning

If a recursive function never reaches its base case, the stack will keep growing.

Eventually Python raises an exception:

  • RecursionError: maximum recursion depth exceeded

This happens because the call stack has a finite size.

This is why every recursive algorithm must have a base case.

Example: Recursive Function without a Base Case

def recurse(depth):
    try:
        return recurse(depth + 1)   # Recursive Call
    except RecursionError as err:          # Catching RecursionError
        return depth, err           # Returns max depth reach, 
                                    # and RecursionError exception object

depth, err = recurse(1)
print(f"{type(err).__name__}:", err)
print("Max Depth:", depth)
Output
RecursionError: maximum recursion depth exceeded
Max Depth: 2978

Disadvantages of Recursion

Disadvantages of Recursion

Recursion can be a very expressive way to describe how a problem should be solved.

However, recursion is often less efficient than iteration.

Reason: function calls are more expensive for Python than simple loop operations.

Every time a function is called, Python must:

  1. Create a new stack frame
  2. Store the function’s parameters
  3. Store the function’s local variables
  4. Record the return location
  5. Later unwind the stack when the function returns

This overhead makes recursive programs slower than equivalent iterative programs.

Iteration vs Recursion

Iteration uses:

  • loops (for, while)
  • a fixed number of variables
  • constant stack usage

Recursion uses:

  • repeated function calls
  • stack frames for each call
  • increasing memory usage as depth grows

Example

Lets compare the execution time between an iteration vs recursive solution to computing the sum of the first n integers:

1+2+3+⋯+n1 + 2 + 3 + \cdots + n

def recursive_sum(n):
    if n == 0:
        return 0
    else:
        return n + recursive_sum(n - 1)
def iterative_sum(n):
    total = 0
    for i in range(n + 1):
        total += i
    return total

Remarks

Recursion provides clarity and elegance, but it comes with costs:

  • slower execution
  • increased memory usage
  • potential recursion depth limits

In Python:

  • Recursion is useful for expressing certain algorithms clearly
  • Iteration is usually more efficient

Recursion is commonly used for:

  • tree algorithms (computing the size of a directory)
  • divide-and-conquer algorithms (sorting algorithms, Tower of Hanoi problem)
  • backtracking (Sudoku solvers, maze solving, generating permutations)
