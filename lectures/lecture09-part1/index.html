Linear Data Structures

What Are Linear Structures?

We begin our study of data structures with several simple but powerful ideas:

  • Lists
  • Stacks
  • Queues
  • Deques

These are examples of collections of data where the items have an order.

Once an item is added to the structure:

  • it keeps its position relative to the other elements
  • the structure maintains a linear ordering

Because of this property, these structures are called linear data structures.

Ends of a Linear Structure

A linear structure can be thought of as having two ends.

Different terms may be used to describe these ends:

  • left / right
  • front / rear
  • top / bottom

The specific names are not important.

What does matter is:

  • where items are added
  • where items are removed

Operations Define the Structure

Different linear structures behave differently based on how items enter and leave the structure.

Examples:

  • Some structures allow insertion at only one end
  • Some allow removal from both ends
  • Some allow insertion and removal from the same end

These differences lead to some of the most important data structures used in algorithms.

Understanding these behaviors allows us to solve many computational problems efficiently.

Abstract Data Types, Public Interfaces, and Implementations

Introduction

In computer science we separate three related ideas:

  1. Abstract Data Types (ADT)
  2. Public Interfaces
  3. Implementations (Data Structures)

An ADT describes the logical behavior of a data structure.

The public interface specifies the operations that external code is allowed to use.

An implementation describes how those operations are carried out in memory.

This separation allows the same ADT and interface to be implemented in multiple ways.

Abstract Data Types (ADT)

An Abstract Data Type defines the concept of a structure.

It describes:

  • the kind of data being organized
  • the rules governing how the data behaves
  • the operations that should exist

The ADT does not specify how the data is stored.

Examples of ADTs:

  • Collection
  • List
  • Stack
  • Queue
  • Deque

Each ADT defines rules about how elements can be added, removed, or accessed.

Public Interface

The public interface is the collection of operations that programs are allowed to use when interacting with an ADT.

It defines:

  • what operations are available
  • what each operation does
  • what inputs and outputs are expected

The public interface does not reveal how the operations are implemented internally.

Instead, it provides a contract between the user of the structure and the implementation.

Example: List ADT Public Interface

Typical operations for the List ADT include:

  • append(x)
    Adds the element x to the end of the list.

  • add(x) Adds the element x to the front of the list

  • insert(i, x)
    Inserts the element x at index i.

  • remove(i)
    Removes and returns the element at index i.

  • get(i)
    Returns the element stored at index i without modifying the list.

  • set(i, x)
    Replaces the element at index i with the new value x.

  • size()
    Returns the number of elements currently stored in the list.

These operations define what a list can do, but not how it is implemented.

Implementations (Data Structures)

A data structure is a concrete implementation of an ADT.

It specifies:

  • how the data is stored in memory
  • how each interface operation is performed

Different implementations can support the same public interface but may have different performance characteristics.

Example Implementations of the List ADT

Two common implementations of the List ADT are:

  • ArrayList
  • LinkedList

Both implementations support the same public interface, but they store and manage data differently.

Performance (Big-O Notation)

Big-O Notation

When studying data structures, we often ask questions such as:

  • Is inserting into a list fast?
  • Is removing an element efficient?
  • Is accessing an element by index expensive?

Different implementations of the same Abstract Data Type can perform these operations at very different speeds.

To compare these differences, computer scientists use a concept called Big-O notation.

Big-O notation gives us a way to describe how the running time of an operation grows as the data gets larger.

What Big-O Notation Measures

Big-O notation describes how the number of operations grows as the input size increases.

We usually denote the input size by:

  • n\mathrm{n} = number of elements in the data structure

Rather than measuring exact running time (which depends on the computer and programming language), we focus on:

  • How the work grows as n grows.

Example:

  • O(1)O(1) constant time
  • O(n)O(n) linear time

These expressions tell us how an operation scales as the data structure becomes larger.

Example: Searching a List

Suppose we store a collection of numbers in a Python list.

To find a particular value, we may need to check each element one at a time.

Worst case:

  • the value is at the end of the list
  • or it may not be present at all

This means we may examine every element.

If the list has n elements, we may perform up to n comparisons.

This type of growth is written as:

O(n)O(n)

This is called linear time.

def contains(lst, target):

    for item in lst:
        if item == target:
            return True

    return False

Example: Dictionary Lookup

Now consider a Python dictionary.

  • Dictionaries store data using keys.
  • When looking up a key, Python can usually go directly to the correct location.

This means the number of operations does not depend on how many items are stored.

Even if the dictionary grows larger, the lookup time stays approximately the same.

This behavior is written as:

O(1)O(1)

This is called constant time.

grades = {
    "Alice": 92,
    "Bob": 85,
    "Charlie": 78
}

print(grades["Alice"])

Why This Matters

As programs scale to larger datasets, the difference between growth rates becomes important.

Example:

  • List search –> O(n)O(n)
  • Dictionary lookup –> O(1)O(1)

If we have only a few elements, the difference may be small.

But with millions of elements, the performance difference can become dramatic.

Big-O notation helps us compare these behaviors.

We will use Big-O notation to analyze the performance of data structures such as stacks, queues, and linked lists.

List ADT

The List Abstract Data Type (ADT)

A List ADT defines the concept of an ordered collection of elements:

A List is an ordered collection of elements.

Key properties:

  • Elements are stored in a linear sequence
  • Each element has a position (index) in the sequence
  • Indices typically range from 0 to n − 1
  • The list may contain duplicate elements
  • The list may be empty

Mathematically, a list can be represented as:

L=[a0,a1,a2,…,an−1]L=[a_0,a_1,a_2,\ldots,a_{n−1}]

where:

- $a_i$​ is the element at index $i$
- $n$ is the number of elements.

List Puiblic Interface

The public interface of the List ADT specifies the operations that programs are allowed to use when interacting with the list.

Typical operations in the List public interface include:

  • append(x) –> add item to the end of the list
  • add(x) –> add item to the front of the list
  • insert(i, x) –> insert element x at position i
  • remove(i) –> remove and return the element at position i
  • get(i) –> access the element at index i
  • set(i, x) –> replace the element at index i with x
  • size() –> return the number of elements in the list
  • is_empty() –> returns True if list contains no elements

Remark:

The ADT defines the behavior and public interface of the structure, but it does not specify how the data is stored internally.

Time Complexity

When the backing storage fills up, the Array List has to allocate a new, larger array and copy all the existing elements into it.

That copy step takes time proportional to the number of elements in the list

Thus the time complexity of resizing is

  • O(n)O(n)

Array List Append Operation

Time Complexity

Appending to a dynamic array (Array List) usually just stores the element (constant time O(1)O(1)), but every so often it has to resize the buffer.

If you do nn appends starting from empty, the total work is O(n)O(n), so on average each append is O(1)O(1).

We express this by saying that the time complexity of append is

  • O(1)O(1) amortized

Array List Insertion

Inserting into the middle requires shifting elements.

Time complexity

Due to the elements needed to be shifted, the time complexity of insert is

  • O(n)O(n)

Array List Remove

Removing from the middle requires shifting elements.

Time complexity

Due to the elements needed to be shifted, the time complexity of remove is

  • O(n)O(n)

Linked List

Storage (Nodes)

A Linked List stores data in a separate data structure called a node.

Each node contains:

  • data
  • a reference to the next node (next)

Remarks:

  • temp is the variable name bound to the node instance.
  • The node contains the value data = 93.
  • The next reference points to Python’s special None object, which is denoted by the ground symbol in the image above.

Linked List Structure

A linked list only keeps track of the first node.

All other nodes are accessed by following references.

Remarks:

  • mylist is the variable name binded to the linked list instance
  • The head of the linked list refers to the first node which contains the first item of the list.
  • The tail of the linked list refers to the node that is at the end of the linked list. The tail usually referrence the None object (denoted by the ground symbol)

Important:

It is very important to note that a liked list itself does not contain any node objects. Instead it contains a single reference to only the first node (head) in the linked structure.

Linked List Traversal

Traversal refers to the process of systematically visiting each node. This process is used heavely when mutating linked lists.

Steps for traversal:

  • Use an external reference (current) that starts at the first node in the list.
  • As we visit each node, we move the reference to the next node by “traversing” the next reference. This moves current along the the linked list
  • We stop when current is referencing None

Time complexity

To travers the entire linked list, we need to visit all nn nodes. Thus the time complexity is O(n)O(n)

Linked List Append

Appending requires traversing the linked list.

Step 1: Traverse the linked list until you reach the tail node

  • The tail node is identified because its next reference is None.

Step 2: Update the tail node so its next reference points to the new node.

Time Complexity

Since you must traverse the entire linked list to locate the tail, the time complexity is:

  • O(n)O(n)

Linked List Add (Front)

Adding a node (temp) to the front of a linked list does not require traversal.

Step 1: Set the new node’s next reference to the current head node.

Step 2: Update the head pointer so it now references the new node.

The new node becomes the first element of the linked list.

Time Complexity

Since no traversal of the list is required, the time complexity is:

  • O(1)O(1)

Important Note

The order of Steps 1 and 2 matters.

If you update head before setting temp.next, the reference to the original list will be lost.

Since the only entry point to the list is the head pointer, overwriting it first causes all previously existing nodes to become unreachable.

In other words, the remainder of the linked list would no longer be accessible from the program.

Linked List Insert

Inserting a node at a given index i requires traversing the linked list.

Step 1: Traverse the linked list until you reach the node at index i - 1.

Step 2: Update the node being inserted so its next reference points to the node currently at index i.

Step 3: Update the node at index i - 1 so its next reference points to the new node.

Time Complexity

Since the linked list must be traversed to locate the insertion position, the time complexity is:

  • O(n)O(n)

Linked List Remove

Removing a node at a given index i requires traversing the linked list.

Step 1: Traverse the linked list until you reach the node at index i - 1.

Step 2: Identify the node to be removed (the node currently at index i).

Step 3: Update the node at index i - 1 by redirecting next reference to the node at index i + 1.

This bypasses the node at index i, effectively removing it from the list.

Time Complexity

Since the linked list must be traversed to locate the node before the removal position, the time complexity is:

  • O(n)O(n)
