  • append(x) for an ArrayList is amortized O(1) because occasional resizing requires copying the array.

Experiment

Lets run an experiment comparing how ArrayList and LinkedList perform for two common operations:

  • accessing an element with get(i) and
  • adding a new element at the beginning of the list with add(x).

The goal is to connect the theoretical time complexity we discuss in class with actual measured runtimes.

By running the same operations on lists of different sizes, we can observe how performance changes as nn grows.

This helps show why

  • ArrayList is efficient for indexed access,
  • why LinkedList is slower for get(i), and
  • why inserting at the front is much more costly for an ArrayList than for a LinkedList.
Operation ArrayList LinkedList
get(i) O(1) O(n)
add(x) O(n) O(1)

Setup

For each n=10,102,…,105n = 10, 10^2, \dots, 10^5, we construct an ArrayList and a LinkedList of size nn. We then compare the performance of:

  • ArrayList.get(i) vs LinkedList.get(i)
  • ArrayList.add(x) vs LinkedList.add(x)

Notes:

  • When executing get(i), we will be taking the middle index i = n // 2
  • To reduce measurement noise and system jitter, the times presented are averages computed from many runs of the experiment.

Results

Remarks:

  • ArrayList.get(i) is O(1) because the element can be accessed directly by index.
  • LinkedList.get(i) is O(n) because we must walk through the nodes from the front until we reach index i.

For adding at the beginning of the list, the behavior is reversed in practice:

  • ArrayList.add(x) at the front is O(n) because all existing elements must be shifted one position to the right,
  • while LinkedList.add(x) at the front is O(1) because we only create a new node and update the head reference.

Very small timing results, especially for n = 10, may look a bit noisy because constant overhead and measurement noise can dominate when the list is tiny. The overall trend as n grows is the important part.

Storage

ArrayList Memory Layout

An ArrayList stores its elements contiguously in memory.

This means that elements are placed next to each other in a single block of memory.

Example layout:

Key properties:

  • Elements are stored in order and next to each other
  • The address of element i can be computed directly
  • This allows constant-time indexing (O(1)O(1))

Example:

value = my_list[i]

The computer can compute the location of element i immediately.

Important consequence:

  • Very fast random access
  • Insertion in the middle requires shifting elements

LinkedList Memory Layout

A LinkedList does not store elements contiguously in memory.

Instead, each element is stored inside a node object.

Nodes are connected by assigning a node object to the next attribute of another node.

A LinkedList object itself stores a reference to the first node in the list.
This reference is typically bound to the attribute head.

Because each node is an independent object, the nodes may be stored anywhere in memory.

Important consequences:

  • Efficient insertions and removals (only references change)
  • No direct indexing — nodes must be reached by following references from the head

Final Remarks

When to Use an ArrayList

  • Fast random access — accessing elements by index (get(i)) is very efficient.
  • Better cache performance — elements are stored contiguously in memory.
  • Simple iteration — sequential scanning is typically faster.
  • Most common general-purpose list when inserts/removals in the middle are rare.

When to Use a LinkedList

  • Frequent insertions at the front of the list (add(x)).
  • Frequent insertions or removals once a position is already known.
  • No resizing overhead — nodes are added dynamically without copying elements.
  • Useful for structures like stacks, queues, and deques where operations occur at the ends.
