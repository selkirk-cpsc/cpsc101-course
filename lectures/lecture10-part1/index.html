Stacks (Informal Introduction)

The Stack Data Structure

A stack is an ordered collection of items with the following rule:

  • Items are added and removed from the same end

This end is called the top of the stack.

The opposite end is called the base of the stack.

Stack Ordering Principle

Stacks follow a specific ordering rule:

LIFO — Last In, First Out

Meaning:

  • The most recently added item is removed first.
  • The oldest item remains near the base.

Basic Stack Operations

Let s denote a stack.

Basic Operations:

  • s.push(x) –> adds x on top of the stack
  • s.pop() –> removes (and returns) x from the top of the stack

In the following example the top of the stack is on the right:

    s = [bottom, ..., top]
Stack Operation Stack Contents Return Value
s.push(4) [4]
s.push('dog') [4, 'dog']
s.push(True) [4, 'dog', True]
s.push(8.4) [4, 'dog', True, 8.4]
s.pop() [4, 'dog', True] 8.4
s.pop() [4, 'dog'] True
s.pop() [4] dog
s.pop() [ ] 4

Stacks in Computer Systems

Stacks are used internally by many computer systems and algorithms.

A familiar example is the Back button in a web browser.

When you visit pages:

      Page A --> Page B --> Page C --> Page D

The pages are stored in a stack of URLs.

      Top   -->   Page D (current page)
                  Page C
                  Page B
      Base  -->   Page A

Pressing Back removes the top page and returns you to the previous one.

Remarks

Stacks are important because they allow us to:

  • reverse the order of items
  • manage nested operations
  • track program execution (call stacks)
  • solve many algorithmic problems

Because of their simplicity and power, stacks appear throughout computer science and programming.

Stack Abstract Data Type (ADT)

Abstract Model

A Stack is an ordered collection of elements that follows the Last-In, First-Out (LIFO) rule.

If the stack contains elements

$ S = [a_0, a_1, a_2, \dots, a_{n-1}] $

then:

  • a0a_0 is the bottom of the stack
  • an−1a_{n-1} is the top of the stack
  • only the top element is directly accessible

The stack may be empty.

Public Interface

The public interface of the Stack ADT defines the operations that can be performed on the stack:

is_empty()

  • Returns True if the stack has no elements
  • Returns False otherwise
  • The stack is not modified

size()

  • Returns the number of items currently stored in the stack
  • The stack is not modified

push(x)

  • Adds a new item to the top of the stack
  • Requires one parameter (the item x)
  • Returns nothing
  • The stack is modified

pop()

  • Removes and returns the top item
  • Requires no parameters
  • The stack is modified

peek()

  • Returns the top item
  • Does not remove the item
  • The stack is not modified

Behavioral Guarantees

The Stack ADT, through its public interface, guarantees:

  1. LIFO ordering — the most recently added element is removed first
  2. Restricted access — only the top element can be accessed or removed
  3. Encapsulation — users interact only through the public interface
  4. Implementation independence — behavior is fixed, representation is not

Implementing Stack ADT

Goal

Implement the Stack ADT using an ArrayList as the underlying storage.

We will:

  1. Define the Stack ADT (public interface)
  2. Assume an existing ArrayList implementation of List ADT
  3. Implement ArrayStack that inherits from StackADT
  4. Use only ArrayList operations

Step 1: Stack ADT (Public Interface)

The Stack ADT defines required behavior:

  • push(x)
  • pop()
  • peek()
  • is_empty()
  • size()

The StackADT class given below provides the interface only, not an implementation.

  class StackADT:
      def size(self):
          raise NotImplementedError

      def is_empty(self):
          raise NotImplementedError

      def push(self, x):
          raise NotImplementedError

      def pop(self):
          raise NotImplementedError

      def peek(self):
          raise NotImplementedError

Step 2: Assumed ArrayList Interface

We assume an existing ArrayList implementation with the following public interface:

  • append(x) –> add item to the end of the list
  • remove(i) –> remove and return the element at position i
  • get(i) –> access the element at index i
  • size() –> return the number of elements in the list
  • is_empty() –> returns True if the list contains no elements

We will treat ArrayList as a black box that satisfies the List ADT.

Key Design Decision

We map the top of the stack to the end of the ArrayList.

If the stack is:

$ [a_0, a_1, a_2] $

then:

  • a2a_2 is the top
  • corresponds to index size() - 1

Step 3: ArrayStack Implementation

Constructor

class ArrayStack(StackADT):

    def __init__(self):
        self._data = ArrayList()

Implement size() and is_empty()

    def size(self):
        return self._data.size()

    def is_empty(self):
        return self._data.is_empty()

Implement push(x)

Add element to the top of the stack.

Key idea:

  • Top = end of ArrayList
  • Use append(x)
    def push(self, x):
        self._data.append(x)

Example:

Before: [a0,a1][a_0, a_1]

After push(x): [a0,a1,x][a_0, a_1, x]

Implement pop()

Remove and return the top element.

Key idea:

  • Top index = size() - 1
  • Use remove(i)
    def pop(self):
        if self.is_empty():
            raise IndexError("pop from empty stack")

        top_index = self.size() - 1
        return self._data.remove(top_index)

Example:

Before: [a0,a1,a2][a_0, a_1, a_2]

After pop():

  • returns a2a_2
  • stack becomes [a0,a1][a_0, a_1]

Implement peek()

Return the top element without removing it.

Key idea:

  • Top index = size() - 1
  • Use get(i)
    def peek(self):
        if self.is_empty():
            raise IndexError("peek from empty stack")

        top_index = self.size() - 1
        return self._data.get(top_index)

Example:

Before: [a0,a1,a2][a_0, a_1, a_2]

After peek():

  • returns a2a_2
  • stack unchanged

Complete Implementation

    class ArrayStack(StackADT):

        def __init__(self):
            self._data = ArrayList()

        def size(self):
            return self._data.size()

        def is_empty(self):
            return self._data.is_empty()

        def push(self, x):
            self._data.append(x)

        def pop(self):
            if self.is_empty():
                raise IndexError("pop from empty stack")
            return self._data.remove(self.size() - 1)

        def peek(self):
            if self.is_empty():
                raise IndexError("peek from empty stack")
            return self._data.get(self.size() - 1)

        def __str__(self):
            if self.is_empty():
                return "[]"
            return f"{str(self._data)} (top={self.peek()})"

        def __repr__(self):
            if self.is_empty():
                return f"ArrayStack(_data=[])"
            else:
                return f"ArrayStack(_data={self._data}, top={self.peek()!r})"

Important Point About Encapsulation

Even though _data has more methods (_data = ArrayList()), users of ArrayStack should not interact with _data directly.

They should only use:

  • push(x)
  • pop()
  • peek()
  • size()
  • is_empty()

So the extra methods on _data are an internal implementation detail.

Key Takeway:

“The user sees the Stack public interface, not the internal storage object”
