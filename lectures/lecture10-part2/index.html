Balancing Parentheses

What Does Balanced Mean?

Parentheses are balanced when:

  1. Every opening parenthesis ( has a matching closing parenthesis ).
  2. Parentheses are properly nested.

Examples of balanced parentheses:

   (()()()())

   (((())))

   (()((())()))

Examples of unbalanced parentheses:

   ((((((())   # missing closing parenthesis

   )()()(      # not properly nested

   (()()(()    # missing closing parenthesis

Applications

Recognizing balanced symbols is important in many applications, such as:

  • programming language parsers
  • compilers
  • expression evaluation

Goal

Write a program that determines whether a string of parentheses is balanced:

par_checker("(((())))")  # returns True
par_checker("(()")       # returns False

### Observation

As we read a string **from left to right**: 

- The **most recent opening parenthesis** must match the **next closing parenthesis**.
- Matching occurs from the **inside out**.

Example:

Matching order:
1st close --> matches most recent open
2nd close --> matches the earlier open

This is exactly the behavior of a **stack** (**Last-In, First-Out (LIFO)**).

### Balanced Parentheses Algorithm

We can solve the problem using a **stack**.

Algorithm outline:

1. Start with an **empty stack**.
2. Scan the string **from left to right**.
3. If an **opening parenthesis** is encountered:
   - push it onto the stack.
4. If a **closing parenthesis** is encountered:
   - pop the stack.
5. If a closing parenthesis appears when the stack is empty:
   - the expression is **not balanced**.
6. After processing the entire string:
   - the stack should be **empty** for the expression to be balanced.

#### Important conditions:

- If we **cannot pop** when encountering a closing parenthesis --> unbalanced.
- If the **stack is not empty at the end** --> unbalanced.

Only when:

- all symbols are processed **and**
- the stack is empty

do we conclude the parentheses are **balanced**.

### Implementation

```python
from ArrayStack import  ArrayStack

def par_checker(symbolString):

    s = ArrayStack()
    balanced = True         # tracks whether the string remains valid
    index = 0               # moves through the string one symbol at a time

    while index < len(symbolString) and balanced:

        symbol = symbolString[index]

        if symbol == "(":   # Opening parentheses are pushed onto the stack
            s.push(symbol)

        else:
            if s.is_empty(): # If the stack is empty when encountering `)`, the string is invalid
                balanced = False
            else:           # Closing parentheses trigger popping a previous opening parenthesis
                s.pop()

        index = index + 1

    return balanced and s.is_empty() # Checks for balanced conditions
print(par_checker("((()))"))     # properly nested parentheses
print(par_checker("(()"))        # missing a closing parenthesis
print(par_checker(")(()"))       # incorrect nested parentheses
Output
True
False

Balanced Symbols (General Case)

Understanding the General Case

In many programming languages, multiple types of symbols must be balanced and properly nested.

Examples in Python:

  • () –> used for tuples and arithmetic expressions
  • [] –> used for lists
  • {} –> used for dictionaries

A valid expression must satisfy two conditions:

  1. Every opening symbol has a corresponding closing symbol.
  2. The types of symbols must match.

Examples of Balanced Symbol Strings

The following symbol strings are properly balanced:

    { { ( [ ] [ ] ) } ( ) }
    [ [ { { ( ( ) ) } } ] ]
    [ ] [ ] [ ] ( ) { }

Properties of these examples:

  • every opening symbol has a closing symbol
  • symbols close in the correct order
  • each symbol type matches correctly

Examples of Unbalanced Symbol Strings

The following examples are not balanced:

    ( [ ) ]
    ( ( ( ) ] ) )
    [ { ( ) ]

Common problems include:

  • closing the wrong symbol type
  • missing closing symbols
  • incorrect nesting order

Extending the Parentheses Algorithm

The previous parentheses-checking algorithm can be extended easily.

The core stack idea remains the same:

  1. Scan the string from left to right.
  2. Push opening symbols onto the stack.
  3. When a closing symbol appears, pop the stack.
  4. Check whether the popped symbol matches the closing symbol.

If the symbols do not match, the string is not balanced.

At the end:

  • the stack must be empty
  • otherwise some symbols were never matched

Balanced Symbol Algorithm

Additional logic is required:

When a closing symbol is encountered:

  • remove the top opening symbol
  • check that the parentheses match

Example matches:

( matches )
[ matches ]
{ matches }

Example mismatches:

( does not match ]
[ does not match )
{ does not match )

A helper function can be used to perform this comparison.

def matches(open, close):

    opens = "([{"
    closers = ")]}"
    return opens.index(open) == closers.index(close)

print(matches("{", "}"))
print(matches("[", ")"))
print(matches("(", "}"))

Applications

Stacks play a crucial role in processing programming languages.

Examples include:

  • checking balanced expressions
  • parsing program syntax
  • evaluating mathematical expressions

Almost every programming language contains nested structures, and stacks are the natural data structure for managing them.

Evaluating Expressions

Infix Notation

Infix notation is the standard way we write arithmetic expressions:

  • The operator is placed between its operands

Examples:

3 + 2
(3 + 2) * 4
(8 - 3) / 5

Postfix Notation (Reverse Polish Notation)

Postfix notation is a way of writing arithmetic expressions:

  • The operator comes after its operands
  • No parentheses are needed
  • The order of operations is unambiguous

Examples:

Infix Expression Postfix Expression
A + B * C + D A B C * + D +
(A + B) * (C + D) A B + C D + *
A * B + C * D A B * C D * +
A + B + C + D A B + C + D +

Applications

Postfix notation is important because it provides a simple and reliable way to evaluate expressions.

In standard (infix) notation:

  • Expressions require parentheses and precedence rules (PEMDAS)
  • Evaluation can be ambiguous without strict rules
  • More complex for computers to parse and evaluate

Postfix notation removes this complexity:

  • No parentheses needed
  • No precedence rules required
  • Evaluation order is built into the expression

Where Is It Used?

  • Calculators (especially stack-based calculators)
  • Compilers and interpreters (expression evaluation)
  • Programming languages (internal expression parsing)
  • Mathematical software systems

Infix –> Postfix (Operator Handling)

Converting from Infix (standard) notation to Postfix can be done with a Stack.

Below we walk through the steps how how this can be done.

Note: We will not be dealing with the case where the infix expressions has parentheses.

Operator Precedence

Higher precedence operators are evaluated first.

Common precedence levels:

Precedence level Operators
Highest ^
Next *, /
Lowest +, -

(All are left-associative except ^)

Rule for Handling Operators

Let op_stack denote a stack containing the operators
"^", "*", "/", "+", and "-".

When reading a new operator op_new:

Case 1: The stack is empty

  • Push op_new onto the stack.

Case 2: The stack is not empty

While:

  • the stack is not empty, and
  • precedence(op_top) ≥\geq precedence(op_new)

do:

  • pop op_top from the stack and add it to the output.

Then:

  • push op_new onto the stack.

Important Remark

When handling a new operator, you may need to pop more than one operator from the stack before pushing op_new.

This simplified rule assumes there are no brackets in the infix expression.

Example

Let op_stack denote a Stack.

Convert: A * B + C * D

Step Action / Reasoning Stack Output
Read A Operand –> add to output [ ] A
Read * Stack empty –> push * [ * ] A
Read B Operand –> add to output [ * ] A B
Read + Compare with * –> * has higher precedence –> pop *, then push + [ + ] A B *
Read C Operand –> add to output [ + ] A B * C
Read * Compare with + –> * has higher precedence –> push [ +, * ] A B * C
Read D Operand –> add to output [ +, * ] A B * C D
End Pop * –> add to output [ + ] A B * C D *
End Pop + –> add to output [ ] A B * C D * +

Final Expression

Postfix expression: A B * C D * +

Remarks

The stack ensures that:

  • higher-precedence operators are applied first
  • parentheses and precedence rules are handled automatically
  • no ambiguity remains in the final expression

Example (with brackets)

Convert: (A + B) * (C - D / (E + F)) + G

Final Expression (Postfix)

A B + C D E F + / - * G +

Remarks:

  • We will not go into the full details of handling brackets (parentheses) during the conversion process.
  • Postfix notation eliminates the need for brackets entirely:
    • it produces expressions that are unambiguous and straightforward to evaluate computationally.

Evaluating Postfix Expressions

Evaluate from left to right:

3 2 + 4 * 5 1 - /
=> 5 4 * 5 1 - /
=> 20 5 1 - /
=> 20 4 /
=> 5

At each step:

  • Apply the operator to the previous two values
  • Replace them with the result

Remarks:

  • Each operator applies to the two most recent values
  • No need for precedence rules (e.g., PEMDAS)
  • Evaluation can be implemented using a stack data structure
