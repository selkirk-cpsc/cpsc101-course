Queues (Informal Introduction)

What Is a Queue?

A queue is an ordered collection of items where:

  • New items are added at one end, called the rear
  • Existing items are removed from the other end, called the front

As elements enter the queue:

  • They start at the rear
  • They move toward the front
  • They wait until it is their turn to be removed

FIFO Ordering

Queues follow a specific ordering principle:

FIFO — First In, First Out

This means:

  • The first item added is the first item removed
  • The most recent item added must wait at the rear

Another common way to describe this rule is:

First-Come, First-Served

Basic Queue Operations

Assume we start with an empty queue q:

  • q = [front, ..., rear]

Basic Operations:

  • q.enqueue(x) –> Adds an item to the rear of the queue
  • q.dequeue() –> Removes and returns items from the front of the queue
Operation Queue Contents Return Value Front Rear
q.enqueue(4) [4] 4 4
q.enqueue('dog') [4, 'dog'] 4 'dog'
q.enqueue(True) [4, 'dog', True] 4 True
q.enqueue(8.4) [4, 'dog', True, 8.4] 4 8.4
q.dequeue() ['dog', True, 8.4] 4 'dog' 8.4
q.dequeue() [True, 8.4] 'dog' True 8.4
q.dequeue() [8.4] True 8.4 8.4
q.dequeue() [ ] 8.4 None None

Applications

Queues are widely used in computer systems.

Example 1: Printer Queue

  • A computer lab has many computers
  • All students send print jobs to one printer

The printer behaves like a queue:

  1. Print tasks enter the queue
  2. The first task submitted prints first
  3. Later tasks must wait their turn

This is a direct application of FIFO ordering.

Example 2: Queues in Operating Systems

Operating systems also use queues internally:

Process Scheduling:

  • Programs waiting to run are placed in process queues
  • The operating system decides which program runs next

Keyboard Input Buffer

When typing quickly:

  • Keystrokes may occur faster than they appear on screen
  • The system temporarily stores them in a queue-like buffer

This ensures characters appear in the correct order.

Queue Abstract Data Type (ADT)

Abstract Model

A Queue is an ordered collection of elements that follows the FIFO — First In, First Out rule.

If the queue contains elements

$ q = [a_0, a_1, a_2, \dots, a_{n-1}] $

then:

  • a0a_0 is the front of the queue
  • an−1a_{n-1} is the rear of the queue
  • only the front is directly accessible
  • elements can only be added to the rear of the queue

The queue may be empty.

Public Interface

The public interface of the Queue ADT defines the operations that can be performed on the stack:

is_empty()

  • Returns True if the queue has no elements
  • Returns False otherwise
  • The queue is not modified

size()

  • Returns the number of items currently stored in the queue
  • The queue is not modified

enqueue(x)

  • Adds a new item to the rear of the queue
  • Requires one parameter (the item x)
  • Returns nothing
  • The queue is modified

dequeue()

  • Removes and returns the item at the front of the queue
  • Requires no parameters
  • The queue is modified

front()

  • Returns the item at the front of the queue
  • Does not remove the item
  • The queue is not modified

Behavioral Guarantees

The Queue ADT, through its public interface, guarantees:

  1. FIFO ordering — the last added element is removed first
  2. Restricted access — only the front element can be accessed or removed
  3. Encapsulation — users interact only through the public interface
  4. Implementation independence — behavior is fixed, representation is not

Implementing Queue ADT

Goal

Implement the Queue ADT using a LinkedList as the underlying storage.

We will:

  1. Define the Queue ADT (public interface)
  2. Assume an existing LinkedList implementation of List ADT
  3. Implement LinkedQueue that inherits from QueueADT
  4. Use only LinkedList operations

Step 1: Queue ADT (Public Interface)

The Queue ADT defines required behavior:

  • enqueue(x)
  • dequeue()
  • front()
  • is_empty()
  • size()

This class provides the interface only, not an implementation.

  class QueueADT:
      def size(self):
          raise NotImplementedError

      def is_empty(self):
          raise NotImplementedError

      def enqueue(self, x):
          raise NotImplementedError

      def dequeue(self):
          raise NotImplementedError

      def front(self):
          raise NotImplementedError

Step 2: Assumed LinkedList Interface

We assume a LinkedList implementation with the following public interface:

  • add(x) –> add to front
  • append(x) –> add to end
  • remove(i) –> remove at index i
  • get(i) –> access element at index i
  • size() –> return the number of elements in the list
  • is_empty() –> returns True if the list contains no elements

We treat LinkedList as a black box that satisfies the List ADT.

Key Design Decision

We map:

  • front of queue –> index 0
  • rear of queue –> index size() - 1

So if:

  • q=[a0,a1,a2]q = [a_0, a_1, a_2]

then:

  • a0a_0 = front (removed first)
  • a2a_2 = rear (added last)

Step 3: LinkedQueue Implementation

Constructure

class LinkedQueue(QueueADT):

    def __init__(self):
        self._data = LinkedList()

Implement size() and is_empty()

    def size(self):
        return self._data.size()

    def is_empty(self):
        return self._data.is_empty()

Implement enqueue(x)

Add element to the rear of the queue.

Key idea:

  • Rear = end of LinkedList
  • Use append(x)
    def enqueue(self, x):
        self._data.append(x)

Example:

Before: [a0,a1][a_0, a_1]

After enqueue(x): [a0,a1,x][a_0, a_1, x]

Implement dequeue()

Remove and return the front element.

Key idea:

  • Front = index 0
  • Use remove(0)

Precondition:

  • queue must not be empty
    def dequeue(self):
        if self.is_empty():
            raise IndexError("dequeue from empty queue")
        return self._data.remove(0)

Example:

Before: [a0,a1,a2][a_0, a_1, a_2]

After dequeue():

  • returns a0a_0
  • queue becomes [a1,a2][a_1, a_2]

Implement front()

Return the front element without removing it.

Key idea:

  • Front = index 0
  • Use get(0)
    def front(self):
        if self.is_empty():
            raise IndexError("front from empty queue")
        return self._data.get(0)

Example:

Before: [a0,a1,a2][a_0, a_1, a_2]

After front():

  • returns a0a_0
  • queue unchanged

Complete Implementation

    class LinkedQueue(QueueADT):

        def __init__(self):
            self._data = LinkedList()

        def size(self):
            return self._data.size()

        def is_empty(self):
            return self._data.isEmpty()

        def enqueue(self, x):
            self._data.append(x)

        def dequeue(self):
            if self.isEmpty():
                raise IndexError("dequeue from empty queue")
            return self._data.remove(0)

        def front(self):
            if self.isEmpty():
                raise IndexError("front from empty queue")
            return self._data.get(0)

        def __str__(self):
            if self.is_empty():
                return "[]"
            return f"{self._data} (front={self.front()})"

Important Point About Encapsulation

Even though _data has more methods (_data = LinkedList()), users of LinkedQueue should not interact with _data directly.

They should only use the queues public interface:

  • enqueue(x)
  • dequeue()
  • front()
  • size()
  • is_empty()

So the extra methods on _data are an internal implementation detail.

Key Takeway:

“The user sees the Queue public interface, not the internal storage object”

Self Check

Suppose a queue q has elements added in the following order:

60, 10, 50, 30, 40, 20

What is the output of the code below?

while not q.is_empty():
    print(q.dequeue(), end=" ")

A. 10 20 30 40 50 60
B. 60 10 50 30 40 20
C. 60 50 40 30 20 10
D. 20 40 30 50 10 60
E. There is no guaranteed order

Answer:

B. 60 10 50 30 40 20 (FIFO — First In, First Out)

Why is enqueue(x) O(n)?

If your LinkedList:

  • does not maintain a tail pointer

then:

  • append(x) requires traversal to the end
  • cost is O(n)O(n)

Optimization

If LinkedList maintains a tail reference, then:

  • append(x) becomes O(1)O(1)

Updated complexity:

Operation LinkedQueue (with tail)
enqueue(x) O(1)O(1)
