Searching Algorithms

What is a Searching Algorithm?

A searching algorithm is a step-by-step procedure used to locate a specific item (or determine its absence) within a collection of data.

Searching is one of the most fundamental operations in computer science

Real-World Applications

  • Web Search Engines — Google, Bing, and DuckDuckGo index billions of pages and retrieve relevant results in milliseconds.
  • Database Queries — Every SQL SELECT relies on efficient search techniques under the hood.
  • GPS & Navigation — Finding the shortest route between two points involves searching through graphs of roads and intersections.
  • E-Commerce — Product catalogs use search to match filters, keywords, and recommendations to inventory.
  • Spell Checkers & Autocomplete — Your phone keyboard searches a dictionary of words as you type each letter.
  • Genomics & Bioinformatics — Researchers search through DNA sequences to find gene patterns and mutations.

Common Searching Algorithms We Will Cover

Linear Search - check every element one by one

Binary Search - divide and conquer (requires sorted data)

Linear Search

How It Works

  1. Start at the first element
  2. Compare the current element with the target
  3. If it matches, return the index
  4. If not, move to the next element
  5. If you reach the end, the target is not found
def linear_search(lst, target):
    """
    Return the index of the first occurrence of target in lst,
    or -1 if target is not in lst.
    """
    for idx, _ in enumerate(lst):
        if lst[idx] == target:
            return idx
    return -1
data = random.choices(range(1, 11), k=10)
print(data)

targets = [data[3],99]

for t in targets:
    result = linear_search(data, t)
    if result == -1:
        print(f"{t} not found")
    else:
        print(f"{t} found at index {result}")
Output
[1, 5, 8, 5, 9, 4, 6, 8, 10, 4]
5 found at index 1
99 not found

Built-in Linear Search

Python has it’s own built in linear search:

list.index()

The index() method performs a linear search and returns the index position of the first matching element.

If the element is not found, it raises a ValueError.

You can also pass optional start and stop arguments to search within a slice of the list.

data = [10, 20, 30, 20, 40]

targets = [20, 50]

for t in targets:
    # list.index(x) rasies ValueError if x us not found
    try:
        print(f"{t} found at index {data.index(t)}")
    except ValueError as err:
        print(err)
Output
20 found at index 1
50 is not in list

Comparing list.index and in vs linear_search

Let’s compare our linear_search with Pythons built in list.index() method and in operator.

def compare_searches(arr, target):
    """
    Compares the python list.index and in operator to our linear search
    
    Args:
        arr - list of numbers to search
        target - the number to search for
        
    Returns times for each search (list.index,in,linear_search)
    """
    
    start1 = time.perf_counter()
    arr.index(target)
    stop1 = time.perf_counter()

    start2 = time.perf_counter()
    target in arr
    stop2 = time.perf_counter()
    
    start3 = time.perf_counter()
    linear_search(arr,target)
    stop3 = time.perf_counter()
    
    return stop1-start1, stop2-start2, stop3-start3

  • All three searches are linear — time grows proportionally with the amount of data: O(n)O(n)

  • The list.index method and in operator is quicker than our implementation

    • Both list.index and in are written in C — much faster than a Python loop.

Final Remark

The in operators implemenation depends on the data structure:

  • For Lists and Tuples, Python performs a linear search
    • complexity is O(n)O(n)
  • For Sets and Dictionaries, Python uses a hash table lookup (discussed later) — it computes a hash (unique-ish id) of the target value and jumps directly to the correct bucket.
    • time complexity of O(1)O(1), making it dramatically faster for large collections.
# Searching a list vs a set — same syntax, very different performance

data_list = list(range(10_000_000))
data_set = set(data_list)

target = 9_999_999  # Worst case for linear search

# List: O(n) — scans all 10 million elements
start = time.time()
found = target in data_list
print(f"List search: {time.time() - start:.4f}s")  # ~0.1-0.3s

# Set: O(1) — hash lookup, nearly instant
start = time.time()
found = target in data_set
print(f"Set search:  {time.time() - start:.6f}s")  # ~0.000001s

Binary Search

Introduction

Binary search is an alternative to linear search — much faster, but the list must be sorted first.

Real-life example: Finding a name in a phone book:

  • Open to the middle
  • Immediately know which half to look in next
  • After 2 checks, you’ve eliminated 3/4 of the entries!

Each step divides the remaining data in half –> divide and conquer

How It Works

Requires sorted data

  1. Set low=0 and high=len-1
  2. Calculate mid = (low + high)//2
  3. If arr[mid] == target, return mid
  4. If target > arr[mid], search right half
  5. If target < arr[mid], search left half
  6. Repeat until low > high 
def binary_search(arr, target):
    low = 0
    high = len(arr) - 1

    while low <= high:
        mid = (low + high) // 2 # Grab middle value
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            low = mid + 1       # Searching right half
        else:
            high = mid - 1      # Search the left half

    return -1                   # If target not found, return -1
sorted_data = [21, 33, 34, 56, 60, 75, 77, 90, 121, 130]

for target in [121, 999]:
    result = binary_search(sorted_data, target)
    print("target:", target, f", Found at index {result}" if result != -1 else ", Not Found")
Output
target: 121 , Found at index 8
target: 999 , Not Found

Recursive Binary Search

We can also write binary search recursively — the function calls itself on a smaller half each time.

def binary_search_recursive(lst, target):
    if len(lst) == 0:
        return -1
    else:
        midpoint = len(lst) // 2
        if lst[midpoint] == target:
            return midpoint
        elif lst[midpoint] < target:
            result = binary_search_recursive(lst[midpoint + 1:], target)
            return -1 if result == -1 else result + midpoint + 1
        else:
            return binary_search_recursive(lst[:midpoint], target)
sorted_data = [21, 33, 34, 56, 60, 75, 77, 90, 121, 130]

for target in [34, 999]:
    result = binary_search_recursive(sorted_data, target)
    print("target:", target, f", Found at index {result}" if result != -1 else ", Not Found")
Output
target: 34 , Found at index 2
target: 999 , Not Found

Binary Search Analysis

Each comparison eliminates half the remaining items:

Comparisons Items Remaining
1 n2\dfrac{n}{2}
2 n4\dfrac{n}{4}
3 n8\dfrac{n}{8}
⋮\vdots ⋮\vdots
k n2k\dfrac{n}{2^k}

Worst case kk:

$ \begin{align} \frac{n}{2{k+1}} < 1 \leq \frac{n}{2k} &\rightarrow \frac{n}{2} < 2^k \leq n \ &\rightarrow \log_2(n) - \log_2(2) < k \leq \log_2(n) \ &\rightarrow \log_2(n) -1 < k \leq \log_2(n) \end{align} $

But kk is a positive integer, thus:

k=log2(n) k = \log_2(n) .

In other words, the time complexity for binary search is O(log2n)O(\log_2 n)

Worst case for 10,000,000 items:

Built-In Binary Search

The bisect Module

The bisect module implements binary search on sorted sequences. It is written in C under the hood, making it extremely fast. The key functions are:

  • bisect_left(arr, target) — finds the leftmost insertion point for target in sorted list arr. If target is already present, the insertion point is before (to the left of) any existing entries.
  • bisect_right(arr, target) — finds the rightmost insertion point. If target is already present, the insertion point is after (to the right of) existing entries.
  • insort_left(arr, target) and insort_right(arr, target) — insert target into a while keeping arr sorted.

The search itself is O(log n), but insertion with insort is O(n) because shifting elements in a list takes linear time.

import bisect

# bisect_left vs bisect_right
sorted_data = [10, 20, 30, 30, 30, 40, 50]
target = 30

# bisect_left: insertion point BEFORE existing 30s
left_insert_point = bisect.bisect_left(sorted_data, target)
print(f"Left insertion point of {target}: index {left_insert_point}")   # 2

# bisect_right: insertion point AFTER existing 30s
right_insert_point = bisect.bisect_right(sorted_data, target)
print(f"Right insertion point of {target}: index {right_insert_point}")  # 5
Output
Left insertion point of 30: index 2
Right insertion point of 30: index 5
# Using bisect to build a binary search function

def binary_search_bisect(sorted_list, target):
    """Use bisect to perform an exact-match binary search."""
    i = bisect.bisect_left(sorted_list, target)
    if i < len(sorted_list) and sorted_list[i] == target:
        return i
    return -1
for target in [30, 999]:
    result = binary_search_bisect(sorted_data, target)
    print("target:", target, f", Found at index {result}" if result != -1 else ", Not Found")
Output
target: 30 , Found at index 2
target: 999 , Not Found

Summary: Choosing the Right Tool

Tool Algorithm Time Returns Raises Error?
x in list Linear search O(n)O(n) True / False No
x in set Hash lookup O(1)O(1) amort True / False No
list.index(x) Linear search O(n)O(n) Index position Yes
bisect_left() Binary search O(logn)O(\log n) Insertion point No

Rule of thumb:

  • Use in with a set for fast membership checks.
  • Use bisect when working with sorted data you need to search repeatedly.
  • Use list.index() when you need the position and the list is small or unsorted.
